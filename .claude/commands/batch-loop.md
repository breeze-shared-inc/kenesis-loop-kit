# /batch-loop

外部駆動バッチ（`scripts/batch_loop.py`・1チケット=1セッション）のプリフライト検証を代行実行し、人間がターミナルで実行すべきコマンドラインを提示してください。**このコマンドはバッチ本体を実行しません** — バッチはトークン累積を避けるため、チケットごとに `claude -p "/start-loop {ID}"` を新規セッションで起動する駆動スクリプトを人間がセッション外で実行します（運用ガイド: `docs/batch-loop.md`）。

## 手順

1. $ARGUMENTS からチケットID列を読み取る（スペース区切り・記載順が実行順）
   - 形式: `{チケットID} {チケットID} ...`（例: `APP-001 APP-002 APP-003`）
   - IDが1件以下の場合は連続実行の意味がないため、次を案内して終了する: 対話セッションで進めるなら `/start-loop {ID}`、ヘッドレス単発なら `claude -p "/start-loop {ID}" --permission-mode acceptEdits` をターミナルで実行する
2. プリフライトを代行実行する（読み取り専用・セッションは起動されない）

   ```bash
   python3 scripts/batch_loop.py --dry-run {ID-1} {ID-2} ...
   ```

3. 結果を人間へ提示する
   - **NG（exit 2）**: 違反一覧（P1〜P9）をそのまま提示し、解消方法（`/triage`・チケット整理・`--allow-missing-spec` 等、dry-run出力の案内に従う）を添えて終了する
   - **OK（exit 0）**: dry-run出力の「実行コマンドライン」を提示し、**人間がターミナルで実行する**よう案内する。あわせて次を伝える
     - 実行時に承認サマリが表示され、**そのy/N応答がバッチ事前承認の実体**であること
     - 実行中は同じリポジトリで対話セッションや別バッチを開かないこと（二重ライター防止）
     - 停止条件（異常終了・blocked・未完了・active/残存done・範囲外変更・差し戻し増分）で人間へ報告して中断し、最終チケット後は必ず停止すること
4. `docs/SPEC.md` が無いプロジェクトでは、SPEC免除が人間承認済みであることを確認したうえで `--allow-missing-spec` 付きのコマンドラインを提示する（未承認なら先に人間の承認を得るよう案内する）

## Never

- **セッション内で `claude -p` を起動しない**（セッションのネスト起動。親セッションが待機・出力を吸うためトークン累積の解消にならない）
- **`scripts/batch_loop.py` を `--dry-run` 以外で実行しない**（バッチ本体の起動と承認は人間がターミナルで行う。`--yes` による承認の代行も禁止）
- チケット・SPEC.mdへ書き込まない（`--dry-run` は読み取り専用）

## 使用例

```
/batch-loop APP-001 APP-002
/batch-loop APP-001 APP-002 APP-003
```
