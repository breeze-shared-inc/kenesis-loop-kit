# [KLK-006] SPECのID指向部分抽出スクリプト追加 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-006 に対応します。implementer・tester・reviewerが参照します。

## 1. 目的

チケットに記載されたREQ/SCR/IF-ID（トレーサビリティ規約。定義: SPEC_TEMPLATE.md冒頭規約、転記先: docs/policy-registry.md）を使い、investigator/architect/reviewerがdocs/SPEC.mdの該当セクションのみを優先して読む標準手順を確立する。新規CLI `extract_spec_section.py` を追加し、`check_spec_structure.py` の見出しパーサ（`split_sections`/`split_subsections`/`table_key_ids`）を流用してID→該当セクション・見出しパスの逆引きを行う。存在しないIDは「該当なし」を明示し、エージェントの誤読・ハルシネーションを防ぐ。

投稿時点でチケット概要が想定していた「見出し記法」（`## REQ-001: ...`）は、投稿後の実物SPEC_TEMPLATE.mdの調査（investigation.md §3）により誤りと判明している。REQ/SCR/IF-IDは見出しではなく§5・§6配下の表の主キー列に記載される。本設計はこの実物仕様に基づく。

## 2. 現状

```
   個別ID→該当セクションの逆引きは提供しない
```

## 3. 設計方針

**採用する方針:**

1. **新規CLI `extract_spec_section.py` を `check_spec_structure.py` と同ディレクトリに追加する。** ロジックの複製ではなく `sys.path.insert(0, スクリプトの自ディレクトリ); import check_spec_structure as checker`（`scripts/list_tickets.py`が`_ticket_lib`を取り込む手法と同型）で関数を直接呼び出す。`check_spec_structure.py`のパース仕様（セクション分割・小見出し分割・表主キーID抽出）が変わればそのまま追随でき、二重メンテナンスを避ける。

2. **ID→所属先の対応表を静的定数として持つ（表主キー方式）。** チケット概要の「見出し記法」は実物と不一致（investigation.md §3）なため採用しない。
   ```python
   PREFIX_LOCATIONS = {
       "REQ": (5, ("Must", "Should", "Could"), "startswith"),
       "SCR": (6, ("画面一覧",), "exact"),
       "IF": (6, ("提供インターフェース一覧",), "exact"),
   }
   ```
   REQの小見出しは実物で `Must(必須)` のようにサフィックスを伴うため `startswith` 判定（`check_spec_structure.py`の`must_bodies`判定と同じ方式）。SCR/IFの小見出し名はテンプレート表記と完全一致するため `exact` 判定。

3. **抽出粒度は「小見出し単位」を採用する（investigation.md §次エージェントへの引き継ぎ推奨事項3の解決）。** 該当ID一行のみの抽出は表ヘッダ・列名を失い単体では意味を読み取れない。セクション全体（§5/§6全体）の抽出はMust/Should/Could等の無関係な行まで混入しトークン削減という目的に反する。`split_subsections()`が既に切り出す小見出し単位（表ヘッダ＋同居する全行を含む）が、無関係情報を含まず単体で意味が完結する最小境界であり、これを採用する。小見出しが存在しない旧形式SPEC（`check_spec_structure.py`が同じ状況をWARNする形式）では、対象セクション本文全体へフォールバックする。

4. **「該当なし」は3系統に分けて非エラーで出力し、いずれも exit 0 とする。** (a) SPEC内に定義未検出、(b) EH/NFR/OQ等スコープ外プレフィックス、(c) `<PREFIX>-\d{3}`形式に一致しない不正形式。AC2「存在しないIDを指定した場合はエラーではなく該当なしを明示出力する」の対象をID関連の失敗全般に広げ、エージェントがどんなID文字列を渡しても本スクリプトが非ゼロ終了で委縮しないようにする。exit 2はファイル未検出・引数不足・デコード失敗（`check_spec_structure.py`と同じ契約）のみに限定する。

5. **`.claude/hooks/guard_bash_writes.py` の `READONLY_SCRIPTS` へ新規スクリプトを追加する（スコープに含める）。** investigator/reviewerはBashツールで本スクリプトを実行する設計であり、`docs/SPEC.md`を引数に取るBashコマンドは登録なしでは`guard_bash_writes.py`により一律denyされる（`mentions_guarded()`は保護対象パスを引数に含むBashコマンドを既定denyし、例外はALLOWED_HEADSまたはREADONLY_SCRIPTSの完全パス一致のみ）。登録しない場合、AC4「抽出スクリプトで優先して読む」はinvestigator/reviewerにとって実行不能な指示になり、本チケットの目的（SPECの部分参照を標準の読み方にする）が達成できない。追加は`check_spec_structure.py`と全く同型の1行追加であり、`is_readonly_script_call()`のロジック自体は変更しないため、リスクは低い（詳細は§6）。

6. **architectは新方針の対象から機構的に除外されるため、Grep+Read代替方式を明記する。** architect.mdのtools frontmatnterはBashを含まない（`Read, Grep, Glob, Write, Edit`）。AC4はinvestigator/architect/reviewerの3エージェント全てへの追記を求めるが、architectはそもそも`python3`を実行できない。architectにBashを付与する案は「エージェント権限の変更」であり、architectのConstraint「Preserve public interfaces unless explicitly approved」と本チケットのAC外変更に該当するため採用しない（代替案表参照）。architect.mdへの追記は「Grep（ID文字列のテーブル行検索）→Read（offset/limit指定の部分読み）」という、既存ツールのみで完結する同等の代替手順とする。効果（全文読みをフォールバックへ回す）は他2エージェントと同じであり、AC4の実質的な意図を損なわない。

7. **`docs/policy-registry.md`へ1行追加、CLAUDE.md本体は無編集。** CLAUDE.md「再肥大化の防止」の2手順（実行責任者ファイルへ正を定義→表へ1行追加）に厳密に従う。正は各agents/*.mdのTicket Integration本文と`.claude/hooks/guard_bash_writes.py`が持つ。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| チケット概要どおり見出し記法（`## REQ-001: ...`）を直接パースする設計 | 実物のSPEC_TEMPLATE.mdと不一致（investigation.md §3）。見出しにIDが来ない実データでは常に不一致になり機能しない |
| 該当行1行のみを抽出する最小粒度 | 表ヘッダ・列名が失われ、抽出結果単体では列の意味が読み取れない。小見出し単位の方が実用的な最小コンテキストになる |
| セクション全体（§5/§6全体）を抽出粒度にする | Must/Should/Could等、無関係な要件も混入し、部分抽出によるトークン削減効果が薄れる（目的である「必要な部分だけ読む」に反する） |
| architectにもBashツールを付与し、他2エージェントと同じ形でスクリプトを直接実行させる | エージェント権限（tools frontmatter）の変更は「Preserve public interfaces unless explicitly approved」に反し、本チケットのAC外の変更を伴う。Grep+Readで同等の部分読み効果を代替できるため不要 |
| `check_spec_structure.py`の正規表現ロジックを新規スクリプトへコピー（複製） | パーサ変更時に二重メンテナンスが必要になり、既存スクリプト変更への追随漏れリスクが高い。sys.path.insert方式での関数流用（list_tickets.py/batch_loop.pyと同型）を採用し単一の正とする |
| guard_bash_writes.pyのREADONLY_SCRIPTS登録を見送り、常にReadツールでdocs/SPEC.mdを直接読む運用にする | AC4「抽出スクリプトで優先して読む」がinvestigator/reviewerにとって実行不能な指示になり、本チケットの目的（SPECの部分参照を標準の読み方にする）を達成できない。登録は`check_spec_structure.py`と同型の低リスクな追加であるため見送る理由がない |

**主要なインターフェース（`extract_spec_section.py`、Python）:**
```python
"""SPEC.md からID指定でREQ/SCR/IF該当セクションのみを抽出するCLI。

見出しパーサはcheck_spec_structure.pyを流用する(sys.path.insert方式。
scripts/list_tickets.pyが_ticket_lib.pyを取り込む手法と同型)。
テンプレートの構造(セクション番号・小見出し名)を変更した場合は、
check_spec_structure.py・tests/test_check_spec_structure.pyに加えて
本スクリプトのPREFIX_LOCATIONSとtests/test_extract_spec_section.pyも
追随させること。

本スクリプトは読み取り専用であり、書き込み経路を持たない。
.claude/hooks/guard_bash_writes.py はこの前提で「SPEC.mdを引数に取る本
スクリプトの実行」を許可している(READONLY_SCRIPTS)。書き込み処理を
追加してはならない。

使い方: python3 extract_spec_section.py <SPEC.mdのパス> <ID> [<ID> ...]
終了コード: 0=正常終了(個々のIDが「該当なし」でも0) / 2=引数不足・
           ファイルなし・デコード失敗
"""
import os
import re
import sys

_SCRIPTS_DIR = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, _SCRIPTS_DIR)
import check_spec_structure as checker  # noqa: E402

# 各プレフィックスの (定義セクション番号, 対象小見出し名, 判定方式)。
# REQは小見出しが「Must(必須)」のようにサフィックスを伴うためstartswith、
# SCR/IFは完全一致するためexactで判定する。
PREFIX_LOCATIONS = {
    "REQ": (5, ("Must", "Should", "Could"), "startswith"),
    "SCR": (6, ("画面一覧",), "exact"),
    "IF": (6, ("提供インターフェース一覧",), "exact"),
}
# 本スクリプトの対象外だがSPEC_TEMPLATE.mdで定義されている他のID系統
# (該当なし理由の文言を分けるためだけに使う。抽出ロジックはPREFIX_LOCATIONS外)
KNOWN_OTHER_PREFIXES = ("EH", "NFR", "OQ")


def classify(id_):
    """id_ を判定し (prefix_or_None, status) を返す。
    status: "supported" / "unsupported_prefix" / "invalid_format" """
    m = re.match(r"^([A-Za-z]+)-(\d+)$", id_)
    if not m:
        return None, "invalid_format"
    prefix = m.group(1).upper()
    if prefix in PREFIX_LOCATIONS:
        if re.fullmatch(rf"{prefix}-\d{{3}}", id_):
            return prefix, "supported"
        return prefix, "invalid_format"   # 桁数不一致（例: REQ-1, REQ-0001）
    if prefix in KNOWN_OTHER_PREFIXES:
        return prefix, "unsupported_prefix"
    return prefix, "invalid_format"


def find_id(text, prefix, id_):
    """text（HTMLコメント除去済み）からid_を探す。
    戻り値: [(見出しパス, 本文), ...]（空リスト=該当なし。2件以上は
    非準拠SPECでの重複検出であり、呼び出し側でWARN表示する。エラーにしない）"""
    sec_num, wanted_subs, mode = PREFIX_LOCATIONS[prefix]
    sections = checker.split_sections(text)
    if sec_num not in sections:
        return []
    heading, body = sections[sec_num]
    subsections = checker.split_subsections(body)
    matches = []
    for sub_name, sub_body in subsections.items():
        hit = (any(sub_name.startswith(w) for w in wanted_subs) if mode == "startswith"
               else sub_name in wanted_subs)
        if hit and id_ in checker.table_key_ids(sub_body, prefix):
            matches.append((f"{sec_num}. {heading} > {sub_name}", sub_body.strip()))
    if not matches and id_ in checker.table_key_ids(body, prefix):
        # 小見出しの無い旧形式、または対象小見出し外にIDがある非準拠SPECへの
        # フォールバック（check_spec_structure.pyのscreens_body/if_sourceと同じ方針）
        matches.append((f"{sec_num}. {heading}", body.strip()))
    return matches


def main(argv):
    if len(argv) < 3:
        print("使い方: python3 extract_spec_section.py <SPEC.mdのパス> <ID> [<ID> ...]",
              file=sys.stderr)
        return 2
    path, ids = argv[1], argv[2:]
    try:
        text = open(path, encoding="utf-8").read()
    except UnicodeDecodeError as e:
        print(f"読み込み失敗: {e}\nUTF-8で保存されているか確認してください", file=sys.stderr)
        return 2
    except OSError as e:
        print(f"読み込み失敗: {e}", file=sys.stderr)
        return 2

    text = re.sub(r"<!--.*?-->", "", text, flags=re.S)  # check()と同じ前処理

    for id_ in ids:
        print(f"=== {id_} ===")
        prefix, status = classify(id_)
        if status == "invalid_format":
            print("該当なし（ID形式として認識できません。<PREFIX>-NNN 形式で"
                  "指定してください。対応プレフィックス: REQ/SCR/IF）")
        elif status == "unsupported_prefix":
            print(f"該当なし（{prefix}は本スクリプトの対応プレフィックス外です。"
                  "対応: REQ/SCR/IF。EH/NFR/OQ等はdocs/SPEC.mdを直接参照してください）")
        else:
            matches = find_id(text, prefix, id_)
            if not matches:
                print(f"該当なし（SPEC内に{id_}の定義が見つかりません）")
            else:
                if len(matches) > 1:
                    print(f"[WARN] {len(matches)}箇所で検出されました"
                          "（SPECがテンプレート非準拠の可能性。"
                          "check_spec_structure.pyで構造を確認してください）")
                for i, (heading_path, body) in enumerate(matches, 1):
                    if len(matches) > 1:
                        print(f"--- {i}件目 ---")
                    print(f"見出しパス: {heading_path}")
                    print(body)
        print()
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))
```

**処理フロー:**
```
1. argv検証（3未満はusageをstderrに出しexit 2）
2. SPEC.mdをUTF-8で読み込み（失敗時はcheck_spec_structure.pyと同じ例外分岐でexit 2）
3. HTMLコメント除去（check_spec_structure.check()と同じ前処理を踏襲）
4. 引数の各IDについて:
   a. classify()でprefixとstatusを判定
   b. invalid_format / unsupported_prefix は理由別の「該当なし」を出力し次のIDへ（exit 0のまま）
   c. supportedの場合、PREFIX_LOCATIONS[prefix]に基づきsplit_sections→split_subsections→
      table_key_idsで対象小見出しを探索
   d. 見つからなければセクション全体本文でtable_key_idsフォールバック（旧形式対応）
   e. 0件なら「該当なし」、1件ならその見出しパス+本文、2件以上ならWARN+全件を出力（エラーにしない）
5. 全ID処理後、exit 0
```

## 8. ロールバック戦略

全ての変更が追加的（新規ファイルまたは既存ファイルへの追記のみ）であり、Phase単位で独立してrevert可能。

```bash
# Phase単位でのロールバック(すべて追加的変更のため安全に戻せる。逆順に戻す)
git revert <Phase3のコミットハッシュ>   # エージェント定義3ファイル・policy-registry.mdの追記を取消
git revert <Phase2のコミットハッシュ>   # guard_bash_writes.py READONLY_SCRIPTS登録とそのテストを取消
                                        # (取消後は新スクリプトへのBash経由実行が再びdenyに戻る。fail-closedで安全)
git revert <Phase1のコミットハッシュ>   # extract_spec_section.py本体とそのテストを削除
```

Phase2のみをrevertし、Phase3（エージェント定義の「Bash経由で優先して読む」旨の記述）を残したままにすると、実行不能な指示が残るため行わないこと。Phase2をrevertする場合はPhase3もあわせてrevertする（またはPhase3の文言を「全文Readにフォールバックする」よう即座に手動修正する）。
