## 1. 目的

本チケットは `docs/SPEC.md` の要件ではなく、Kit自体（`.claude/hooks/guard_bash_writes.py`）のセキュリティ修正である（KLK-001〜012と同じ性質。spec_version「なし」の理由は上記フロントマター参照）。

`guard_bash_writes.py` の `is_readonly_script_call()`（シンボル名。以下同様に行番号ではなくシンボル名で参照する）は、インタプリタ（`python3`/`python`）の後にある `NAME=VALUE` 形の語を、位置によらず無条件に「環境変数代入の前置き」としてスキップする。しかし bash の環境変数代入前置きは**先頭コマンドより前**にしか成立せず、先頭コマンドより後ろの `NAME=VALUE` はただの引数である。この不一致により `python3 x=y {READONLY_SCRIPT} docs/SPEC.md` のような偽装形が `READONLY_SCRIPTS` の許可経路を偽装し、実際には `x=y` という名前のファイルが実行されるにもかかわらず hook が allow を返す（任意コード実行、`docs/SPEC.md` はドリフト検知のバックストップも無い）。

本設計は `is_readonly_script_call()` を、他の判定箇所（`head_of`/`next_cwd`/`awk_bindings`/git判定）が既に使っている `head_index()` → `head_args()`（「先頭コマンド語より後ろの語」を機械的に取る共通経路）へ一本化し、この非対称を解消する。

## 2. 現状

**現在のフロー（`segment_violation()` 内、`is_readonly_script_call` の唯一の呼び出し元）:**
```
segment_violation(words, ...):
  head = head_of(words)                                  # 先頭コマンド名（環境変数代入前置き・"(" を剥がす）
  if head in ("python3", "python") and is_readonly_script_call(words):
      return None                                         # READONLY_SCRIPTS 経路として allow
  if head not in ALLOWED_HEADS:
      return "'%s' は許可されていません" % head            # python3/python は ALLOWED_HEADS 非収載なので通常はここで deny
  ...
```

`is_readonly_script_call(words)` の現状実装（独自ループ）:
```
seen_interp = False
for word in words:
    if is_assignment_word(word):
        continue                # 代入語は位置を問わず常にスキップ ← ここが原因
    if not seen_interp:
        seen_interp = True      # インタプリタ本体（"python3"/"python" 自身）を消費
        continue
    if word.startswith("-"):
        return False
    return os.path.normpath(word).endswith(READONLY_SCRIPTS)
return False
```

`words = ["python3", "x=y", ".claude/skills/spec-interview/scripts/check_spec_structure.py", "docs/SPEC.md"]` を入力すると:
1. `"python3"` → 代入語でない・`seen_interp` 未設定 → `seen_interp=True` にして継続（インタプリタ本体として消費）
2. `"x=y"` → `is_assignment_word()` が True → 位置を問わず継続（**本来はここで「headより後ろなので代入ではない」と判定すべきだが、その判定が無い**）
3. `"check_spec_structure.py"`（フルパス） → 代入語でなく `seen_interp` 済み → `READONLY_SCRIPTS` と一致 → `True` を返す（**誤り。実際に実行されるのは `x=y`**）

一方、他の判定箇所はすべて `head_index()` を経由しており、この非対称が無い:
```
def head_index(words):
    for index, word in enumerate(words):
        if is_assignment_word(word):
            continue     # 先頭コマンドより前の代入前置きだけをスキップする設計
        if not word.lstrip("("):
            continue
        return index
    return -1

def head_args(words):
    index = head_index(words)
    return list(words[index + 1:]) if index >= 0 else []
```
`head_index()` は「代入語が続く間はスキップし、最初の非代入語を先頭コマンドの位置とする」——すなわち代入語のスキップは**先頭コマンドが確定するまで**に限られる。`head_args()` はその後ろの語をそのまま返すため、先頭コマンドより後ろに現れる `NAME=VALUE` は代入語として扱われず、素の引数として残る。これが `is_readonly_script_call()` に欠けている区別である。

## 3. 設計方針

**採用する方針:**

`is_readonly_script_call(words)` を `head_args()` ベースの実装へ書き換える（investigatorがscratchpad上で実測検証済みの案。KLK-010 reviewerが検証していた案とも一致）。

```python
def is_readonly_script_call(words):
    """`python3 <READONLY_SCRIPTS> <args>` の形か。

    スクリプトパスの前にフラグがある形（`-c`/`-m` 等の別実行経路）は不許可。
    先頭コマンド（python3/python 本体）より後ろの最初の語だけをスクリプト
    候補として見る（head_args と同じ経路）。bash の環境変数代入前置きは
    **先頭コマンドより前**にしか現れないため、先頭コマンドより後ろに現れる
    `NAME=VALUE` は代入ではなく python3 への引数（＝実行対象スクリプトの
    候補）である。これを無条件でスキップしていたことが本チケット（KLK-013）
    の脆弱性の原因だった（`python3 x=y <READONLY_SCRIPT> ...` は実際には
    `x=y` というファイルを実行するのに、`x=y` を読み飛ばして
    `<READONLY_SCRIPT>` を見てしまい allow になっていた）。
    """
    args = head_args(words)
    if not args:
        return False
    first = args[0]
    if first.startswith("-"):
        return False
    return os.path.normpath(first).endswith(READONLY_SCRIPTS)
```

この変更は「代入語の判定」を撤去するのではなく、「代入語のスキップを`head_index()`が既に行っている（先頭コマンド確定前に限る）」ことを再利用し、`is_readonly_script_call` 側では二重に判定しないようにするものである。呼び出し元 `segment_violation` は無変更（`head = head_of(words)` の判定結果と `is_readonly_script_call(words)` の呼び出し方は変わらない。渡す `words` は同じ、返り値の意味〔True=許可経路として成立／False=不成立〕も変わらない）。

**この変更が動作を変える形・変えない形（設計時点の机上検証。Phase 1でinvestigatorのscratch検証結果を実装へ反映し、Phase 2で回帰テストとして固定する）:**

|---|---|---|---|

| `python3 x=y {READONLY_SCRIPT} docs/SPEC.md` | **True（allow・誤り）** | **False（deny）** | 修正対象。AC1（チケット再現手順そのもの） |

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `is_readonly_script_call` 内に「先頭コマンドの位置」を独自ロジックで再計算する（`head_args()` を経由しない最小パッチ） | 本チケットの根本原因は「先頭コマンド判定の経路が1関数だけ独立していたこと」自体であり、独自ロジックを維持すると将来また非対称の穴を生む再発リスクが残る。investigator実測済みの `head_args()` 一本化案は既存経路の再利用のみで新規ヘルパが不要であり、リスクが小さい |
| `is_readonly_script_call` を廃止し `segment_violation` へインライン展開する | 呼び出し元は1箇所のみだが、関数境界を無くすとテスト・ドキュメントからのシンボル参照（本プロジェクトの規約）が失われる。関数として残す方が影響範囲の説明・レビューが容易 |
| `READONLY_SCRIPTS` 例外経路自体を廃止する（`python3`/`python` を完全に不許可にする） | `/setup` 手順5・`/interrogate-spec` Phase 0 の `check_spec_structure.py` 実行導線（CHANGELOG記載の正当な必要性）を破壊する。AC2「正規の許可経路が壊れない」に反するため却下 |
