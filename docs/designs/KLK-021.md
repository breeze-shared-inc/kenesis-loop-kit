## 3. 設計方針

**スコープの前提（investigator申し送りを設計の前提として採用・人間確認は不要と判断）:**
AC群は「メインworktree限定という運用文書化＋ヘッダ可視化」のみを是正手段として明示しており、
`root`解決ロジック自体をcwd非依存にする代替案（例: 絶対パス起動への統一・環境変数での起点強制）は
明示的にスコープ外と読める。本設計はこの解釈——**観測性向上＋運用規約であり、コード側のcwd依存性
そのものは解消しない**——を前提として採用する。したがって`root`省略時の既定値
`Path(__file__).resolve().parents[1]`（cwd依存）はそのまま維持し、変更しない。

**採用する方針:**
1. `main()`の`root`引数評価を、明示指定時は`Path(root).resolve()`へ変更する（AC5・M2・T3）。
   省略時の既定値は現状のまま（cwd依存を残す。上記スコープ前提）。この変更により`active_dir`は
   明示・省略いずれの経路でも常に絶対パスになる。
2. 新規関数`format_target(active_dir)`を追加し、`main()`内で`collect()`実行後・`LEGEND`出力の
   直前に`print(format_target(active_dir))`を挿入する（AC3）。出力される絶対パスは1.の変更により
   保証される。CLI引数は一切追加しない（既存の「パスを表す引数を持たない」設計は不変）。
3. `.claude/commands/start-loop.md`・`.claude/agents/orchestrator.md`それぞれへ、
   「一覧CLIはメインworktreeで実行する」旨の1文を追記する（AC4）。追記文には
   `CLI_INVOCATION`（`tests/test_klk003_doc_wiring.py`が数える`"python3 scripts/list_tickets.py"`
   の完全一致文字列）を含めない言い回し（`` `scripts/list_tickets.py` ``のみ言及）にし、
   既存の出現回数アサーションと無関係にする（§6リスク参照）。
4. T1〜T4はいずれも**新規テストの追加のみ**で完結し、`guard_bash_writes.py`・`_ticket_lib.py`の
   本体コードは変更しない（T1は既存の正しい挙動の固定、T2は既存テストの検証観点の強化、T3・T4は
   1.の変更・既存の設計制約の固定）。
5. ファイルモードは前例（`scripts/batch_loop.py`・KLK-007）に揃え、`chmod +x`
   （`git update-index --chmod=+x`でGit管理下の実行ビットへ反映）とする。shebang
   （`#!/usr/bin/env python3`）は変更せず維持する（AC9）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| `root`解決をcwd非依存化する（`git rev-parse --show-toplevel`・環境変数での起点強制等） | ACが「CLI引数を増やさない」「メインworktree限定の運用文書化＋観測性向上」のみを是正手段として明示しており、cwd依存性自体の解消は明示的にスコープ外と読める（investigator申し送り）。ACの再定義に当たるため不採用 |
| `format_target`の出力位置をLEGENDの後・データ行の前にする | 「対象」は前提情報であり、LEGEND（列の凡例）より先に読者へ伝えるほうが読解順として自然。既存`TestMain`のアサーションは全て`assertIn`の部分一致で順序非依存のため、いずれの位置でも既存テストへの影響はないが、エラーの早期発見という目的には先頭配置が適する |
| T3を`subprocess`でCLIを直接起動して検証する | 既存の`TestMain`は全てin-processで`main()`を直接呼ぶ設計であり一貫性を欠く。subprocessは実行時間・プラットフォーム依存が増えるだけでin-process呼び出しで十分に等価性を検証できる |
| ファイルモードをshebangごと削除し644に統一する | 前例（batch_loop.py）がshebang付き755であり、将来`./scripts/list_tickets.py`の直接実行や`chmod`運用の一貫性を崩す理由がない。機能影響のない軽微修正のため前例踏襲が最小差分 |
| ドキュメント追記文に`CLI_INVOCATION`の完全一致文字列（`python3 scripts/list_tickets.py`）を含める | `tests/test_klk003_doc_wiring.py`の出現回数アサーション（`>= 2`等）は下限チェックのため実害はないが、将来の言い回し変更時に無用な結合を生む。`` `scripts/list_tickets.py` ``のみの言及で要件（AC4の「1文追記」）を満たせるため、より疎結合な言い回しを採用 |

  ```python
  def test_row_is_last_line_of_contiguous_table_block(self):
      lines = self.section.splitlines()
      table_indices = [i for i, ln in enumerate(lines) if ln.strip().startswith("|")]
      target_idx = next(i for i, ln in enumerate(lines)
                        if "scripts/list_tickets.py" in ln)
      blocks, current = [], []
      for idx in table_indices:
          if current and idx != current[-1] + 1:
              blocks.append(current)
              current = []
          current.append(idx)
      if current:
          blocks.append(current)
      containing_block = next(b for b in blocks if target_idx in b)
      self.assertEqual(
          target_idx, containing_block[-1],
          "追加行が表の最終行になっていない(表途中への誤挿入): "
          "行index=%d, 表の最終行index=%d" % (target_idx, containing_block[-1]))
  ```
  主張: 追加行が「セクション内の連続する`|`開始行」という表ブロックの中で最後の行であることを
  検証する。表の途中に別の行が誤って挿入された場合（target_idxがブロックの最後でなくなる）を

- **T3（`tests/test_list_tickets.py::TestMain`）**: 新規メソッド

  ```python
  def test_relative_root_matches_absolute_root(self):
      self.write_ticket("KLK-005_t.md", tid="KLK-005", status="design_done",
                        priority="medium", updated="2026-07-15")
      resolved_root = self.root.resolve()
      abs_rc, abs_out, _abs_err = self.run_main(root=resolved_root)
      cwd_backup = os.getcwd()
      self.addCleanup(os.chdir, cwd_backup)
      os.chdir(str(resolved_root))
      rel_rc, rel_out, _rel_err = self.run_main(root=".")
      self.assertEqual(abs_rc, rel_rc)
      self.assertEqual(abs_out, rel_out)
  ```
  主張: 絶対パス（`resolved_root`）指定時と、そのディレクトリへ`os.chdir`したうえで相対パス
