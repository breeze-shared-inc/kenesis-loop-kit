## 1. 目的

本チケットはKit自身の内部改善であり `docs/SPEC.md` は不使用。要件の正はチケットKLK-005の受け入れ条件AC1〜AC5（下記§9に転記）である。

CLAUDE.mdは全サブエージェント（investigator/architect/implementer/tester/reviewer）起動時とメインセッションに毎回注入される固定トークン費であり、現在21,252バイト・190行（可視行）に達している。うち最大ブロックである「## ポリシー管理の原則」節（150-191行目、7,902バイト＝37.18%）はポリシー編集時にのみ必要な参照表であり、ループ実行時の通常作業には不要なため、`docs/policy-registry.md` へ分離してCLAUDE.mdをスリム化する。

## 3. 設計方針

**採用する方針:**

1. **表本体+締め文を丸ごと `docs/policy-registry.md` へ移設**し、CLAUDE.mdの「## ポリシー管理の原則」見出しは残したまま、中身をイントロ文＋「再肥大化の防止」原則文＋手順1・2（手順2の参照先を新ファイルへ更新）＋新設の1行ポインタ文のみに圧縮する（AC1）。見出し自体は削除しない（`extract_section` が `"## ポリシー管理の原則"` の完全一致で探索するため、削除すると通常のアサーション失敗ではなく `AssertionError("見出しが見つかりません")` という別モードで壊れる。これは維持のまま）。
2. **表内9箇所の「本ファイル」は全て「CLAUDE.md」へ明示置換**する（§4-2に列挙）。表が別ファイルへ移ることで「本ファイル」の指示先が曖昧になるため。ただしCLAUDE.md本体側に残る154行目・158行目内の既存の「本ファイル」表現は、その文自体がCLAUDE.md内に留まり続けるため変更不要（自己参照として引き続き正しい）。
3. **AC1（原則文+ポインタのみ）とAC3（35%以上削減）の両立**は、表本体のみの分離では実測試算で約31.3%にとどまり届かない（investigatorの懸念どおり）。architectが実際の置換文言を手計算（UTF-8バイト換算、以下§4-4に算出根拠を記載）した結果、**「## スラッシュコマンド一覧」節も合わせて圧縮**することで約39.9〜40.8%（安全マージン込み）に到達する設計を採用する。これはAC2の「分離可否の検討」を「はい、分離する」という結論で解決するものであり、根拠は次の3点: (a) investigatorの調査でこの節は現行テスト・hook・スクリプトのいずれからも機械的に参照されておらず分離の技術的リスクがゼロ、(b) README.mdの `## スラッシュコマンド`（211-232行目）に使用例付きの並行表が既に存在し全14コマンドを網羅していることを実物確認済みのため、CLAUDE.mdの表を削って参照ポインタ化しても情報は失われない、(c) AC1の「原則文は残す」という明示要求と衝突せず、AC3必達に不足する約780バイト超を確保できる唯一の現実的な代替経路である。トレードオフとして、sub-agent（investigator/architect/implementer/tester/reviewer）はCLAUDE.md自動注入コンテキストからスラッシュコマンドの引数詳細を失うが、スラッシュコマンドは人間またはorchestratorが対話的に入力するものでありsub-agent自身が発行することはないため実害は小さいと判断した。
4. **回帰テスト2ファイルの参照先変更**: `tests/test_klk003_doc_wiring.py::TestClaudeMdPolicyTable` と `tests/test_klk004_doc_wiring.py::TestClaudeMdPolicyRow` の `setUp` を、`CLAUDE_MD` + 見出し `"ポリシー管理の原則"` から `POLICY_REGISTRY_MD`（新設定数） + 見出し `"ポリシー一覧"` へ差し替える。アサーション本体（内容チェック）は不変（§4-3）。
5. **CHANGELOG.mdの歴史的言及（4箇所）は更新対象外**とする（Unknown解消・§10参照）。**`docs/designs/{KLK-001,002,003,009,011}.md` の過去引用も更新対象外**とする（Unknown解消・§10参照）。
