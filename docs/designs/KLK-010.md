## 3. 設計方針

### 3-1. 採用する方針: 責務を3レイヤに分離する（初版から不変）

| レイヤ | 責務 | 実現手段 | 解決するケース |
|---|---|---|---|
| **L1 字句** | クォート境界を尊重して「演算子」と「語」を分ける。コマンド置換の抽出**と帰属付け** | 自前の走査（クォート状態のみ追跡）＋ 語チャンクは **`shlex.split`** でクォート解除 | A-1・A-3b・A-3c・B-4c・B-6a・**C1** |
| **L2 パス** | 任意のテキストから保護対象パスを検出する | パス様候補の抽出 → `os.path.normpath` → 除外 → 分類 | B-5・B-6b |
| **L3 構文** | ステートメント／パイプ／リダイレクトの単位で書き込みベクタを判定する | L1のトークン列に対する規則適用 | A-2・A-3a・B-4a/b・**C1・C2・H1・M1** |

**AC1（shlex化）への対応の分離（初版から不変）:**
- **演算子の切り出し**は L1 の自前走査が担う（クォート状態を追跡し、**クォート外の演算子だけ**を切り出す）
- **語のクォート解除**は `shlex.split(chunk, comments=False, posix=True)` が担う

**第2版で追加する原則（P1〜P3）— C1/C2/H1 を構造的に再発させないための不変条件:**

- **P1「証拠は失わない」** — L1 がテキストを別の場所（`substs`）へ退避するときは、**退避先を元の位置から一意に引ける識別子**を残す。L3 の判定は「語トークンそのもの」ではなく「語トークンを解決したテキスト」に対して行う。（C1 の再発防止）
- **P2「フォールバックは本経路の部分集合でなく、旧版の上位互換」** — degraded mode は「旧版が持っていた判定要素（ステートメント分割・パイプ分割・パイプライン単位の言及ゲート・リテラルリダイレクト・heredoc）を**すべて**持つ」ことを条件とする。要素を1つでも落としてはならない。（C2 の再発防止）
- **P3「ホワイトリスト追加には書き込みベクタ棚卸しを伴う」** — `ALLOWED_HEADS` にコマンドを足すときは §3-9 の棚卸し表へ行を追加し、「引数だけで書き込み／任意コマンド実行ができる経路」を列挙して規則の要否を判断する。表に行が無いコマンドを `ALLOWED_HEADS` へ入れてはならない。（H1 の再発防止）

### 3-2. L1: 字句レイヤ（クォート走査 + shlex.split + 置換の帰属付け）

1. **前処理**: `\`+改行（行継続）を空白へ畳み、残る改行を `;` へ置換する。
2. **走査**: 文字列を1文字ずつ進めながら、状態（通常／`'` 内／`"` 内）を追跡する。
   - `'` 内: 次の `'` まで全て literal
   - `"` 内: `\` エスケープを消費し、`$(` とバッククォートのみ解釈する
   - 通常: `\` エスケープを消費、`'`/`"` で引用開始、`$(` / `` ` `` / `<(` / `>(` を置換として抽出、**演算子文字 `;&|<>` を最長一致で切り出す**
3. **置換の帰属付け（第2版で変更・C1 根因A/B の修正本体）**: 抽出した置換は内側テキストを `substs[i]` へ記録し、その位置には **インデックス付きプレースホルダ `__KLK_SUBST_{i}__`** を置く。
   - 初版は全置換に同一の不透明語 `__KLK_SUBST__` を置いていたため、「どのプレースホルダがどの置換か」を後段が復元できなかった。`split_statements` は `tokens` のみを分割し `substs` は分割しないため、**出現順カウントによる対応付けも成立しない**（investigator 実測）。インデックスを埋め込むことが、コード構造を大きく変えずに帰属を得る唯一の実効的な手段である。
   - プレースホルダは語構成文字のみからなるため `shlex.split` を安全に通過し、他の語と連結した場合（`"$(echo a)b"` → `__KLK_SUBST_0__b`）でもインデックスは保存される。
4. **失敗時**: 未閉じクォート・未閉じ括弧・末尾の孤立エスケープでは `ValueError` を送出し、**degraded mode（§3-5）へ落とす**。

**プレースホルダ契約（明文化・M4 保守性への対処）:**

| 用途 | プレースホルダを解決するか | 理由 |
|---|---|---|
| 言及ゲート（証拠の収集） | **する** | 置換結果が外側コマンドの引数になる（C1-A） |
| リダイレクト先の判定 | **する** | 置換結果がリダイレクト先になる（C1-B） |
| 変数代入値の判定（`record_assignments`） | **する** | `f=$(echo docs/SPEC.md); cat x > "$f"` |
| `sed` / `awk` の追加規則 | **する** | フラグ・プログラム断片が置換から供給されうる |
| **先頭コマンド名の決定（`head_of`）** | **しない** | 置換をコマンド名の位置に使う形は解決せず**不許可**として扱う（保守側）。旧版も同様に deny していた |
| `find` / `git` の完全一致規則 | **しない** | 完全一致の意味論を保つ。解決すると空白混じりの語になり照合が壊れる |

**解決は「証拠テキストの拡張」であり、判定を緩める方向には決して働かない**（プレースホルダを解決すると保護対象への言及が増えるだけで、減ることはない）。したがって本変更は allow → deny 方向にのみ作用し、新たな false negative を作らない。

### 3-3. L2: パスレイヤ（候補抽出 → 正規化 → 除外 → 分類）

初版から変更なし。適用順序は次のとおり。

```
① 候補抽出   PATHISH_RE.findall(text)        ← トークン境界に依存しない（AC5）
② 正規化     os.path.normpath(候補)          ← ".." を解決（AC4: B-6b）
③ 除外       正規化後のパス成分に ".claude" があれば対象外
④ 分類       tickets/active|done → Templates・_index.md を除いて保護対象
             それ以外は basename == "SPEC.md" なら保護対象
```

- **③を②の後に行うこと**が B-6b の修正の本体。**①が B-5 の修正の本体**。
- ③はパス「成分」の一致（`".claude" in p.split("/")`）で行う。
- tickets の検出は部分文字列（`"tickets/active" in p`）を維持する（判定を狭めないため）。

### 3-4. L3: 構文レイヤ（ステートメント／パイプ／リダイレクト／cwd）

**「証拠があるときだけ deny する」を原則とする。** ただし §3-2 P1 により、証拠の収集は**プレースホルダ解決後のテキスト**に対して行う。

1. **リダイレクト（出力）** — ステートメント単位で判定する。リダイレクト先が
   - **（第2版）プレースホルダを解決したうえで**保護対象パスに言及していれば **deny**（C1-B の修正本体）
   - このコマンド内で保護対象パスを代入された変数を参照していれば **deny**
   - それ以外（未知の変数・解決できない置換）は **allow**
2. **heredoc** — クォート外の `<<` / `<<<` 演算子が、保護対象に言及するステートメントに現れた場合に deny。
3. **言及ゲート** — ステートメント内の全語トークン（リダイレクト先を含む）を**プレースホルダ解決してから** `mentions_guarded` を適用する（C1-A の修正本体）。さらに **cwd が保護対象配下ならゲートを無条件に真**とする（M1 の修正本体・§3-8）。
4. **パイプライン** — ステートメントをパイプ演算子で分割し、どこかの区間が保護対象に言及していれば全区間の先頭コマンドを検査する。
5. **セグメント** — 先頭コマンド（環境変数代入・先頭 `(` を剥がす）が `ALLOWED_HEADS` にあるかを見て、`sed` / `find` / `git` / `awk` の追加規則を適用する。
   - **（第2版）`head_of` は「`(` を剥がすと空になる語」を読み飛ばして次の語へ進む**（M4-5）。
   - **（第2版）先頭語がプレースホルダを含む場合は専用の理由で deny する**（内部識別子を利用者向けメッセージへ漏らさない）。
6. **コマンド置換・プロセス置換** — L1 が抽出した内側テキストを **同じ判定へ再帰**させる（B-6a）。深さ上限 `MAX_SUBST_DEPTH = 3`。上限到達時は「内側が保護対象に言及していれば deny」で打ち切る。
   - **内側方向（置換の中身が書き込み）と外側方向（置換の結果が外側の書き込みへ供給される）は別の経路であり、両方を実装する。** 初版は内側方向しか持っていなかった＝C1。

**判定順序（ステートメント単位）:** ① 出力リダイレクト（証拠ベース・ゲートなし） → ② heredoc（言及ゲートあり） → ③ 言及ゲート → ④ パイプ区間ごとのセグメント検査。①を先に置くことで `check_spec_structure.py ... > docs/SPEC.md` が引き続き deny される（AC6）。

### 3-5. degraded mode（第2版で全面改訂・C2 の修正本体）

#### 発火条件（5系統・investigator が実測で確定）

`find_violation` は `lex()` の `ValueError` を捕捉して degraded へ落とす。`ValueError` の送出元は次の5つで、**いずれも同一の `except ValueError` が受ける**（追加のハンドリングは不要）。

| # | 条件 | 送出元 | 例 |
|---|---|---|---|
| 1 | 未閉じシングルクォート | `lex` 末尾の `if quote:` | `rm tickets/active/X.md #'` |
| 2 | 未閉じダブルクォート | 同上 | `echo "x` |
| 3 | 未閉じバッククォート | `_take_backtick` | `` ls `echo x `` |
| 4 | 未閉じ `$(` / `<(` / `>(` | `_take_subst` | `ls $(echo x` |
| 5 | **末尾の孤立エスケープ**（初版設計に記載なし） | `flush()` 内の `shlex.split` が `ValueError: No escaped character` を送出。`lex` の文字走査は `i + 1 < n` の条件で末尾の `\` を素通しするため、ここで初めて例外化する | `rm tickets/active/X.md \` |

**頻度の実測:** 条件1は `don't` / `can't` / `won't` / `it's` / `let's` / `didn't` / `isn't` / `that's` といった**日常的な英文コメント**で成立する。意図的な `#'` に限らない。degraded mode は「稀な異常入力の受け皿」ではなく**日常的に踏まれる経路**であると想定して設計すること。

#### degraded mode の判定内容（P2 の具体化）

degraded mode は「**旧版（develop）の `find_violation` と同一の判定**」とする。すなわち次のすべてを持たなければならない。1つでも欠けてはならない。

| 要素 | 旧版の実装 | degraded で必須 |
|---|---|---|
| 全体の言及ゲート | `main()` の `mentions_guarded(command)` | 必須 |
| リテラルリダイレクト（コマンド全体走査） | `REDIRECT_RE.finditer(command)` | 必須（`LEGACY_REDIRECT_RE`） |
| heredoc の部分文字列判定 | `"<<" in command` | 必須 |
| **ステートメント分割** | `STATEMENT_RE.split(command)`（`r"&&\|\\\|\\\||;\|\n"`） | **必須（初版が落としていた＝C2）** |
| **パイプ分割** | `statement.split("|")` | **必須（初版が落としていた＝C2）** |
| **パイプライン単位の言及ゲート** | `if not any(mentions_guarded(p) for p in parts): continue` | **必須** |
| セグメント判定 | `segment_violation(part)` | 必須 |

**旧版から意図的に外す唯一の要素:** リダイレクト先が `$` / バッククォートを含むだけで一律 deny する規則（旧 `REDIRECT_RE` 判定の `or "$" in target or "`" in target`）。これは A-3c（AC2）が明示的に解消を要求した誤denyであり、degraded でも復活させない。この1点のみ旧版より緩くなるが、AC2 の要求であり、かつ degraded は「解析不能な入力」限定の経路であるため許容する。

**degraded mode の既知の誤deny（旧版と同一・許容する）:** パイプ分割が素朴なため、`grep -E '^(id|title):' tickets/active/X.md # don't` のように「クォート内 `|`」と「未閉じクォート」が同時に成立する入力は誤denyになる。これは**旧版と完全に同じ挙動**であり回帰ではない。AC2 が要求する A-1（コメントを伴わない形）は正常経路で処理され allow される。この限界は docstring と README に明記する。

**AC1 との関係:** AC1 は「コマンド解析をシェルの字句解析を尊重する方式へ改める」ことを要求している。degraded mode は **`shlex` が字句解析できない入力に限って**発火するフォールバックであり、正常に字句解析できる入力（AC2 の A-1〜A-3c を含む）では一切発火しない。したがって degraded に旧版相当の素朴分割を戻すことは AC1 を弱めない（reviewer は初版でも「AC1 は満たされている」と判定しており、`LEGACY_REDIRECT_RE` の degraded 限定利用が容認されている。本改訂は同じ枠内の追加である）。

**`#` の扱い（初版から不変）:** クォート内・クォート外を問わず `#` を特別扱いしない（`shlex.split` は `comments=False`）。クォート外のコメント除去は行わない（テキストを捨てない＝安全側）。tester 追加テスト `test_unquoted_comment_with_write_after_semicolon_deny` がこの判断を固定しているため、**コメント除去の導入は行わない**（既存テストを壊すため）。

### 3-6. 設計判断（D1〜D5）

#### D1: awk の内蔵リダイレクトは **本チケットのスコープに含める**（第2版で理由3を改訂）

- **理由1（自ら開ける穴は塞ぐ）— 有効。** 旧版は `awk` が `ALLOWED_HEADS` に無く全 awk が deny だった。AC3 に従って `awk` を追加した結果、awk の書き込み経路は**本チケットの変更が原因で新設された** false negative になる。「既存の穴を塞がない」ことと「自分で穴を開ける」ことは別問題であり、後者は許容できない。
- **理由2（SPEC.md にバックストップが無い）— 有効。** `awk '{print > "docs/SPEC.md"}'` は Stop hook のドリフト検知でも捕捉されない。
- **理由3（コストが小さい）— ~~1行の規則で済む~~ → 前提が崩れたため差し替え。** investigator の実測により、変数代入形（`-v NAME=VALUE` / 位置引数 `NAME=VALUE`）はプログラム断片と保護対象が別トークンに割れるため、単一トークン内の共起では検出できない。**awk 専用の束縛解析（約20行）が必要**である。改訂後の理由は「**コストは1行では済まないが、代替案がいずれも AC に抵触する**」— (a) reviewer 提案の「同一セグメント内の共起」は A-3a（AC2）を誤denyに変えることが実測確定、(b) `awk` を `ALLOWED_HEADS` から外すのは AC3 に抵触、(c) 別チケットへの先送りは AC6（回帰させない）に抵触。**AC を満たしたまま採れる選択肢は「本チケットで awk 専用規則を実装する」以外に存在しない。**

**規則（第2版・AW-1〜AW-3）:** 先頭コマンドが `awk` のセグメントに、次のいずれかが成立すれば deny する。

| ID | 条件 | 塞ぐ形 |
|---|---|---|
| **AW-1**（初版から継続） | 保護対象に言及する語が `>` または `\|` を含む | `awk '{print > "docs/SPEC.md"}' x.md`、`awk 'BEGIN{f="docs/SPEC.md"; print > f}'` |
| **AW-2**（新設） | awk の**変数束縛**（`-v NAME=VALUE` / `-vNAME=VALUE` / `--assign NAME=VALUE` / 位置引数 `NAME=VALUE`）の VALUE が保護対象に言及する | `awk -v f=docs/SPEC.md '{print > f}' in.txt`、`awk '{print > f}' f=docs/SPEC.md in.txt`、`awk -f prog.awk f=docs/SPEC.md in.txt`（プログラムが外部ファイルで**見えない**場合も塞ぐ） |
| **AW-3**（新設） | セグメントが保護対象に言及し、かつ**文字列リテラルを除去したいずれかの語**が「`print` / `printf` の後、`;` `}` 改行に達する前に `>` `>>` `\|` が現れる」パターンに一致する | `awk '{print > FILENAME}' tickets/active/X.md`（変数束縛を伴わない形）、`awk '{print \| "cat"}' tickets/active/X.md` |

**AW-2 を「プログラム内で `>` の直後にその変数名が参照されているか」まで見ない理由:** 変数のエイリアス（`awk -v f=docs/SPEC.md '{g=f; print > g}' in.txt`）で簡単に迂回できるため、参照解析は防御として成立しない。**束縛そのものを証拠とする**方が単純かつ堅牢である。副作用として `awk -v f=tickets/active/X.md '{while((getline l < f)>0) print l}'` のような「変数経由の読み取り」も deny になるが、これは旧版と同じ挙動（旧版は全 awk を deny）であり回帰ではない。

**AW-3 が A-3a を誤denyしない根拠:** A-3a `awk -F'|' '{print $1}' tickets/active/APP-001.md` の各語について — `-F|` は `print` を含まない／`{print $1}` は `print` の後 `$1` を経て `}` に達し、`}` は除外文字クラス `[^;}\n]` に含まれないため `>` `|` へ到達できない／パス引数は `print` を含まない。よって不一致＝allow。同様に `awk 'NR>1 {print}'`（`>` が `print` の**前**）・`awk '{if ($1 > 2) print $1}'`・`awk '{gsub(/a|b/,"c"); print}'`（`;` で打ち切り）・`awk '{printf "%s|%s\n", $1, $2}'`（**文字列リテラル除去**により `|` が消える）はいずれも allow のまま。

**一般化（sed）:** 初版どおり `sed` の `w` コマンド（`s/a/b/w FILE`・`/re/w FILE`）を deny する規則を維持する。`sed -f SCRIPT` と GNU sed の `e` フラグは §3-6 D4 のとおり本チケットのスコープ外（旧版から存在する穴）。

#### D2: `_ticket_lib.is_ticket` との判定基準は **統一しない**（初版から不変）

目的（厳密判定 vs 再現率優先）・スコープ（related_files 外・KLK-012 と衝突）・影響半径（3hookへ波及）の3点が根拠。統一しない代わりに、両者が意図的に別基準であることを `guard_bash_writes.py` のモジュール docstring に明記する（実装済み）。

#### D3: 回帰確認スコープは **スイート全体 + 追加分**（第2版で基準線を更新）

- 基準線: `python3 -m unittest discover -s tests` の全件。**Phase 3 完了時点で324件**（`test_guard_bash_writes.py` は60件）。
- pytest は使わない。
- **既存60件は1行も変更しない**（追加のみ）。変更が必要になった時点で設計の誤りなので、implementer は変更せず orchestrator へ報告する。初版の「既存29件」は第1版時点の基準線であり、第2版では**既存60件**へ更新する。

#### D4: `sort -o` / `uniq` 第2位置引数 / GNU sed `e` フラグは **本チケットのスコープ外**（新規チケットへ切り出す）

investigator が新規発見した3件はいずれも **old = new = allow** であり、reviewer の old/new diff 手法では原理的に検出できない「旧版から存在する既存の穴」である。

**スコープ外とする根拠:**
1. **D1 理由1（自ら開けた穴）が適用できない。** `sort` / `uniq` / `sed` はいずれも旧版から `ALLOWED_HEADS` にあり、本チケットの変更で新設された経路ではない。
2. **どの AC も要求していない。** AC3 は `cd`・`pwd`・`awk`・`cut`・`tr`・`echo` の追加を求めるもので `sort`/`uniq`/`sed` に言及しない。AC6 は「回帰させない」であり、old=allow のものは対象外。
3. **sed の `e` フラグは書き込みではなく任意コマンド実行であり、脅威クラスが異なる。** 本チケットの契約は「Bash 経由の**書き込み**が状態検証 hook を迂回するのを塞ぐ」であって、「ホワイトリスト経由の任意コマンド実行を塞ぐ」ではない。後者は `sed` を `ALLOWED_HEADS` に残すかどうかという、より上位の判断（＝人間の承認を要する設計変更）を含む。本チケットに黙って混ぜるべきではない。
4. **リトライ予算がゼロである。** AC 外の変更を増やすほどレビュー面と誤deny面が広がる。C1/C2/H1 の確実な解消を優先する。

**代わりに本チケットで行うこと（残存リスクの明示）:**
- §3-9 の書き込みベクタ棚卸し表に3件を**未対応**として明記する。
- モジュール docstring と `.claude/hooks/README.md` の「既知の限界」に記載する（Phase 5）。
- §6 R12 として深刻度を明記する（特に sed `e` は任意コマンド実行）。
- 新規チケット候補として orchestrator へ申し送る（§10）。

#### D5: 再発防止テストは **固定リスト方式を正とし、old/new 差分は reviewer の手順とする**

| 方式 | 採否 | 理由 |
|---|---|---|
| **固定リスト方式**（旧版が deny していたペイロード集合を定数として test ファイルへ持ち、全件 deny を assert する） | **採用（正）** | (i) hermetic — git・ブランチ・ネットワークに依存しない。(ii) 現行テストのアーキテクチャ（subprocess + stdin JSON・git 依存ゼロ）を維持できる。(iii) **old=allow の潜在穴も同じリストへ書ける**（将来 §3-9 の棚卸しで見つかった穴を追加できる）。(iv) 差分の理由がコード上に文書として残る |
| **`git show develop:...` による old/new 差分**（テスト内で旧実装を復元して比較） | **不採用（テストとしては入れない）** | (i) **非hermetic** — `develop` はブランチ名参照であり、無関係な更新で「old」の基準が静かに変わる。コミットハッシュ固定でも、履歴の書き換え・浅いクローン・アーカイブ後の破綻に弱い。(ii) 現行テストは git 依存ゼロで、導入はアーキテクチャからの逸脱。(iii) **原理的な死角** — sort/uniq/sed-e のような「両方 allow」の穴は検出できない |
| 同上を **reviewer の検証手順**として残す | **採用（補助）** | 未知の新規回帰を自動で拾える唯一の手段。テストではなく §4-8 の検証チェックリスト V-8 として、reviewer が `scratchpad/klk010/` の比較ドライバを**マージベースのコミットを固定して**再実行する手順に位置づける |
| 3つ目の防御: **書き込みベクタ棚卸し（§3-9）** | **採用（プロセス統制）** | 上記2方式のどちらも拾えない「old=allow の穴」は、機械的手段では原理的に検出できない。`ALLOWED_HEADS` を増やすときに人手で棚卸しする規律（P3）のみが対策となる |

### 3-8. cwd 追跡（M1・第2版で新設）

**問題:** `cd tickets/active && rm APP-001.md` は、`cd` が無条件許可（AC3）であり、後続ステートメントの `APP-001.md` が保護対象パターンに一致しないため allow になる（旧版は deny）。

**設計:**
- `find_violation` はステートメントを左から右へ処理する際に **`cwd`（相対または絶対のパス文字列。追跡不能なら `None`）** を持ち回る。
- 各ステートメントは **その時点の `cwd`** で評価される。評価後に、そのステートメントが `cd` であれば `cwd` を更新する（`cd` 自身は常に allow ＝ AC3 を維持）。
- `cwd` が保護対象（`_is_guarded_path(cwd)` が真）なら、**以降のステートメントの言及ゲートを無条件に真**とする。ゲートが真になるだけで、`ALLOWED_HEADS` の判定はそのまま適用される。
- `cd` のオペランドが `$` を含む・プレースホルダを含む・`~` 始まり・オペランド無し（`cd` / `cd -`）の場合は **`cwd = None`（追跡打ち切り）** とし、以降は cwd による強化を行わない（誤deny を避けるため allow 方向へ倒す）。
- 絶対パスは `os.path.join` の性質でそのまま採用され、`/repo/tickets/active` のような形も `_is_guarded_path` が正しく保護対象と判定する。

**安全性:** 本機構は言及ゲートを真にするだけであり、**allow → deny 方向にしか作用しない**。false negative を新規に作ることは構造上ありえない。

**帰結（意図した挙動）:** `cd tickets/active && ls` は allow（`ls` はホワイトリスト）、`cd tickets/active && rm APP-001.md` は deny、`cd tickets/active && cd ../.. && rm foo.md` は allow（cwd がリポジトリルートへ戻るため）。`cd tickets/active && python3 x.py` は deny になる（保護ディレクトリを cwd とする任意実行のため、保守側で正しい）。

**degraded mode でも同じ追跡を行う**（P2「旧版の上位互換」および正常経路との一貫性のため）。`cd` オペランドの解決は同一のヘルパを共用する。

**限界（docstring・README へ明記）:** `cd "$DIR"` / `cd $(...)` のように cwd がリテラルで決まらない場合は追跡できない。

```python
def expand_substs(text, substs):
    """語トークン中のプレースホルダを、対応する置換の内側テキストへ展開する。
    証拠収集専用（判定を緩める方向には働かない）。§3-2 プレースホルダ契約。"""
    if not substs or not SUBST_PLACEHOLDER_RE.search(text):
        return text

    def replace(match):
        index = int(match.group(1))
        if index >= len(substs):
            return match.group(0)          # 利用者が書いた同名リテラル。そのまま残す
        return " %s " % substs[index]      # 前後に空白を入れて語の誤結合を防ぐ

    return SUBST_PLACEHOLDER_RE.sub(replace, text)


def expand_all(words, substs):
    return [expand_substs(w, substs) for w in words]
```

```python
    """語リストの先頭コマンド名を返す（環境変数代入・グループ化の `(` は剥がす）。"""
```

```python
def segment_violation(words, substs=()):
    """パイプ区間（語リスト）単位の違反理由を返す。問題なければ None。
    words は未解決の語リスト。substs を与えるとプレースホルダを解決した
    テキストで sed / awk の追加規則を評価する（§3-2 プレースホルダ契約）。"""
    head = head_of(words)
    if not head:
        return None
    if SUBST_PLACEHOLDER_RE.search(head):
        return "コマンド名の位置にコマンド置換が使われています"
    if head in ("python3", "python") and is_readonly_script_call(words):
        return None
    if head not in ALLOWED_HEADS:
        return "'%s' は許可されていません" % head
    expanded = expand_all(words, substs)          # sed / awk 規則はこちらを見る
    if head == "sed":
        if any(SED_INPLACE_SHORT_RE.match(t) or t == "--in-place" or
               t.startswith("--in-place=") for t in expanded):
            return "sed -i（in-place編集）は許可されていません"
        if any(SED_WRITE_RE.search(t) for t in expanded if is_guarded_token(t)):
            return "sed の w コマンド（ファイル書き出し）は許可されていません"
    if head == "awk":
        reason = awk_violation(expanded)
        if reason:
            return reason
    if head == "find" and any(t in FIND_WRITE_FLAGS for t in words):
        return "find の書き込み系フラグ（-exec/-delete等）は許可されていません"
    if head == "git":
        sub = next((t for t in words[1:] if not t.startswith("-")), "")
        if sub not in ALLOWED_GIT_SUBCOMMANDS:
            return "git %s は許可されていません" % sub
    return None
```

```python
def awk_bindings(words):
    """awk の変数束縛の VALUE を列挙する（-v NAME=VALUE / -vNAME=VALUE /
    --assign NAME=VALUE / 位置引数 NAME=VALUE）。近似解析であり、
    オプションの引数消費までは厳密に追わない（安全側に倒れる）。"""
    values, expect_value = [], False
    for word in words[1:]:
        if expect_value:
            expect_value = False
            match = AWK_ASSIGN_RE.match(word)
            if match:
                values.append(match.group(1))
            continue
        if word in ("-v", "--assign"):
            expect_value = True
            continue
        if word.startswith("-v") and len(word) > 2:
            match = AWK_ASSIGN_RE.match(word[2:])
            if match:
                values.append(match.group(1))
            continue
        if word.startswith("-"):
            continue                       # -F / -f 等のその他オプション
        match = AWK_ASSIGN_RE.match(word)  # 位置引数の NAME=VALUE
        if match:
            values.append(match.group(1))
    return values


def awk_violation(words):
    """awk セグメントの違反理由を返す（§3-6 D1 の AW-1 / AW-2 / AW-3）。"""
    # AW-1: 保護対象に言及する語そのものが > / | を含む
    if any(">" in t or "|" in t for t in words if is_guarded_token(t)):
        return "awk のプログラム内リダイレクト（print > file 等）は許可されていません"
    # AW-2: 保護対象パスを awk 変数へ束縛している（-v / 位置引数）
    if any(is_guarded_token(v) for v in awk_bindings(words)):
        return "awk の変数へ保護対象パスを束縛しています（-v / NAME=VALUE）"
    # AW-3: 保護対象に言及するセグメントで print/printf の出力リダイレクトを使う
    if mentions_guarded(words):
        for word in words[1:]:
            if AWK_OUTPUT_RE.search(AWK_STRING_RE.sub('""', word)):
                return ("awk のプログラム内リダイレクト（print > file 等）は"
                        "許可されていません")
    return None
```

```python
def record_assignments(statement, guarded_vars, substs=()):
    for words in pipe_segments(statement):
        for word in words:
            match = ASSIGN_RE.match(word)
            if not match:
                break
            value = expand_substs(word[match.end():], substs)   # ← 解決する
            if is_guarded_token(value):
                guarded_vars.add(word[:match.end() - 1])


def redirect_violation(statement, guarded_vars, substs=()):
    for index, (kind, value) in enumerate(statement):
        if kind != "op" or op_kind(value) != "redirect_out":
            continue
        if index + 1 >= len(statement):
            continue
        next_kind, target = statement[index + 1]
        if next_kind != "w":
            continue
        if "&" in value and (target.isdigit() or target == "-"):
            continue                                    # 2>&1 等の fd 複製
        resolved = expand_substs(target, substs)        # ← C1-B の修正本体
        if is_guarded_token(resolved):
            return "リダイレクト（> %s）による書き込み" % target
        if any(name in guarded_vars for name in VAR_REF_RE.findall(resolved)):
            return "リダイレクト（> %s）による書き込み" % target
    return None
```

```python
    if reason:
        return reason
    words = [v for k, v in statement if k == "w"]
```

```python
    """`cd DIR` 実行後の作業ディレクトリを返す。追跡不能なら None。"""

        return None
```

#### (h) `degraded_violation`（C2 の修正本体・§3-5 の表を1対1で実装する）

```python
def degraded_violation(command):
    """字句解析できない入力向けのフォールバック。
    **旧版(develop)の find_violation と同じ判定要素をすべて持つ**（§3-5 P2）。
    唯一の意図的な差分は「リダイレクト先が $ / バッククォートを含むだけで
    deny する」規則を復活させないこと（A-3c / AC2 の要求）。"""
    if not mentions_guarded(command.split()):
        return None                                    # 全体の言及ゲート
    for match in LEGACY_REDIRECT_RE.finditer(command):  # リテラルリダイレクト
        target = match.group(1)
        if target.startswith("&"):
            continue
        if is_guarded_token(target):
            return "リダイレクト（> %s）による書き込み" % target
    if "<<" in command:                                # heredoc（旧版と同じ近似）
        return "ヒアドキュメントによる書き込みの可能性"
    cwd = ""
    for statement in LEGACY_STATEMENT_RE.split(command):     # ← C2 の修正本体
        parts = [p for p in statement.split("|") if p.strip()]   # ← C2 の修正本体
        if not parts:
            continue
        words_list = [p.split() for p in parts]
        if cwd_is_guarded(cwd) or any(mentions_guarded(w) for w in words_list):
            for words in words_list:
                reason = segment_violation(words)
                if reason:
                    return reason
        cwd = next_cwd(words_list[0], cwd)              # §3-8 を degraded でも適用
    return None
```

```python
def find_violation(command, depth=0):
    try:
        tokens, substs = lex(command)
    except ValueError:
        return degraded_violation(command)             # §3-5 の5系統すべてを受ける
    for inner in substs:                               # 内側方向（置換の中身が書き込み）
        if depth >= MAX_SUBST_DEPTH:
            if is_guarded_token(inner):
                return "深いコマンド置換の内側で保護対象パスに言及しています"
            continue
        reason = find_violation(inner, depth + 1)
        if reason:
            return reason
    guarded_vars, cwd = set(), ""
    for statement in split_statements(tokens):
        record_assignments(statement, guarded_vars, substs)
        reason = statement_violation(statement, guarded_vars, substs,
                                     cwd_is_guarded(cwd))
        if reason:
            return reason
        segments = pipe_segments(statement)
        cwd = next_cwd(segments[0] if segments else [], cwd)
    return None
```

## 8. ロールバック戦略（第2版で実測に合わせて全面改訂・M3）

**initial 版の「Phase単位コミットのため `git revert {hash}` で Phase 粒度に復帰できる」という記述は誤りであった。** investigator と reviewer の実測（両者一致）:

| 対象 | `git revert` の結果 |
|---|---|
| Phase 1（`4ae9f61`） | **CONFLICT**（`guard_bash_writes.py`・`tests/test_guard_bash_writes.py` の両方） |
| Phase 2（`cc3fdcc`） | **CONFLICT**（テストのみ。本体は auto-merge 成功） |
| Phase 3（`921debf`） | **CLEAN**（文書のみのため） |

Phase 1・2 は後続コミットが同一箇所を重ねて変更しているため、**Phase 粒度の revert は成立しない**。Phase 4 を積むとこの性質はさらに強まる（Phase 4 は Phase 1・2 が書いた関数を直接書き換える）。したがって**ロールバックの単位はコミットではなく「ブランチ全体」または「マージコミット」とする**。

```bash
# (a) 未マージ段階での全体破棄（orchestrator が実施。develop は無傷）
git worktree remove ../kenesis-loop-kit.wt/KLK-010
git branch -D fix/KLK-010-guard-bash-writes-shlex

# (b) develop へマージ後の取り消し（hook ファイル全体が旧版へ戻る）
git revert -m 1 {マージコミットのhash}

# (c) done 化後に問題が発覚した場合
# /rollback KLK-010   （done → implementation_done）
```

**Phase 単位で戻したい場合:** `git revert` ではなく**順方向の修正コミット**（該当規則を無効化する小さな変更）を作る。具体的には、
- **C1 だけを無効化する** → `expand_substs` を恒等関数（`return text`）にする1行変更。
- **C2 だけを無効化する** → `degraded_violation` を旧実装（平坦リスト）へ差し戻す。
- **H1 だけを無効化する** → `segment_violation` の `awk_violation` 呼び出しを削る。
- **M1 だけを無効化する** → `cwd_is_guarded(cwd)` の実引数を `False` 固定にする。

いずれも「誤denyが業務を止めている」緊急時の一時措置であり、実施したら**必ず人間へ報告し、対応する `LEGACY_DENY_COMMANDS` のテストが失敗する**ことを確認する（失敗が保護の後退を可視化する）。

**緊急時の即時回避:** hook 自体が誤denyでループを止める事態になった場合は、`.claude/settings.json` の `hooks.PreToolUse` から Bash マッチャのエントリを一時的に外す（README「注意」の既定手順）。その間チケット宛ての Bash 書き込みは Stop hook のドリフト検知のみが防衛線になり、**`docs/SPEC.md` 宛ては無防備になる**ため、暫定措置に留め人間へ報告する。
