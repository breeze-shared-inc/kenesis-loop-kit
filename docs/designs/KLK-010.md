## 2. 現状

### 2-1. 旧版（develop・merge-base `72ae730`）の性質 — 「old」の定義

```
main()
 └ mentions_guarded(command)            ← command.split() の各トークンに is_guarded_token
      ├ False → allow
      └ True  → find_violation(command)
           ① REDIRECT_RE.finditer(command)   ② "<<" in command
```

**第3版で重要な旧版の性質（H2 の「old=deny」の理由）:** 旧版は `cd` も `awk` も `ALLOWED_HEADS` に持たない。したがって

- `cd tickets/active` を含むコマンド文字列は、**後続に何が来ても** `cd` セグメントの時点で deny された。
- `awk` を含むコマンドは、保護対象に言及すれば**すべて** deny された。

つまり H2 の11形・C3 の5形・C4 の4形が「old=deny」なのは、旧版がそれらを**検出していたからではなく、コマンドごと拒否していたから**である。この事実は §3-8 の設計判断（保護対象 cwd 下では保守側に倒してよい）と、§4-9 V-9 の WEAKER 行分類の根拠になる。

## 3. 設計方針

### 3-1. 採用する方針: 責務を3レイヤに分離する（初版から不変）+ 原則 P1〜P4

| レイヤ | 責務 | 実現手段 |
|---|---|---|
| **L1 字句** | クォート境界を尊重して演算子と語を分ける。コマンド置換の抽出と帰属付け | 自前の走査（クォート状態のみ追跡）＋ 語チャンクは `shlex.split` |
| **L2 パス** | 任意のテキストから保護対象パスを検出する | 候補抽出 → `os.path.normpath` → `.claude` 除外 → 分類 |
| **L3 構文** | ステートメント／パイプ／リダイレクト／**書き込み先オペランド**／cwd の単位で書き込みベクタを判定する | L1のトークン列に対する規則適用 |

**不変条件（原則）— 同じ抜け方を繰り返さないための規約:**

- **P1「証拠は失わない」** — L1 がテキストを `substs` へ退避するときは、退避先を元の位置から一意に引ける識別子を残す。L3 の判定は「語トークンそのもの」ではなく「語トークンを解決したテキスト」に対して行う。（C1 の再発防止・第2版で導入・維持）
- **P2「フォールバックは旧版の上位互換」** — degraded mode は旧版が持っていた判定要素をすべて持つ。1つでも落としてはならない。（C2 の再発防止・第2版で導入・維持）
- **P3「ホワイトリスト追加には書き込みベクタ棚卸しを伴う」** — `ALLOWED_HEADS` にコマンドを足すときは §3-9 の棚卸し表へ行を追加し、**4次元**（§3-10）で経路を列挙する。（H1 の再発防止・第2版で導入）
- **P4「列挙が漏れても deny 側へ落ちる既定を持つ」（第3版で新設）** — **P3 は人間が「気づく」ことに依存しており、C3／C4 で実際に破れた。** したがって、列挙の完全性に依存しない機械的な既定を最低1つ持たなければならない。本設計では次の2つを持つ。
  1. **awk のオプションはホワイトリスト**（`is_safe_awk_flag`）。既知の読み取り専用オプションに一致しない語は deny。新しい gawk オプションが増えても、収載しない限り自動的に deny 側へ落ちる。
  2. **`CWD_SAFE_HEADS`（明示列挙）**。保護対象ディレクトリを cwd とする状況では、この集合に**明示的に収載されていない** head を deny する。`ALLOWED_HEADS` へ head を足しただけでは cwd 下の許可は得られない（＝忘れると deny になる）。
  - 逆に、**採らない**選択も明記する: 「保護対象に言及するセグメントでホワイトリスト済みコマンドが『疑わしい構文』を含めば deny」という包括規則は**採用しない**（§3-7 の却下理由。`NR>1` や `-F'\|'` を誤denyし、AC2 に抵触することが H1 で実測済み）。

### 3-2. L1: 字句レイヤ（第2版から変更なし）

1. **前処理**: `\`+改行を空白へ、残る改行を `;` へ。
2. **走査**: 通常／`'` 内／`"` 内の状態を追跡し、**クォート外の演算子だけ**を最長一致で切り出す。`$(` / バッククォート / `<(` / `>(` は内側テキストを `substs[i]` へ退避し、**インデックス付きプレースホルダ `__KLK_SUBST_{i}__`** を置く。
3. **失敗時**: 未閉じクォート・未閉じ括弧・末尾の孤立エスケープで `ValueError` → degraded mode（§3-5）。

**プレースホルダ契約（第2版で明文化・第3版で1行追加）:**

| 用途 | 解決するか | 理由 |
|---|---|---|
| 言及ゲート（証拠の収集） | **する** | 置換結果が外側コマンドの引数になる（C1-A） |
| リダイレクト先の判定 | **する** | 置換結果がリダイレクト先になる（C1-B） |
| 変数代入値の判定（`record_assignments`） | **する** | `f=$(echo docs/SPEC.md); cat x > "$f"` |
| `sed` / `awk` の追加規則 | **する** | フラグ・プログラム断片が置換から供給されうる |
| **書き込み先オペランド（`sort -o` / `uniq` 出力引数）（第3版）** | **する** | `sort -o $(echo docs/SPEC.md)` を取りこぼさない |
| 先頭コマンド名（`head_of`） | **しない** | 置換をコマンド名の位置に使う形は解決せず不許可（保守側） |
| `find` / `git` の完全一致規則 | **しない** | 完全一致の意味論を保つ（解決は前後に空白を付けるため一致が壊れる） |
| **`cd` のオペランド（`next_cwd`）** | **しない** | 置換は「コマンドの出力」であって移動先パスそのものではない。解決しても意味のあるパスにならないため追跡打ち切り（allow 方向・§3-8 の限界） |

**解決は「証拠テキストの拡張」であり、判定を緩める方向には決して働かない。**

### 3-3. L2: パスレイヤ（初版から変更なし）

```
① 候補抽出   PATHISH_RE.findall(text)   ② 正規化 os.path.normpath
③ 除外       正規化後のパス成分に ".claude" があれば対象外
④ 分類       tickets/active|done（Templates・_index.md を除く） / basename == "SPEC.md"
```

**第3版で明示する帰結（H2 の設計に直結）:** `_is_guarded_path` は tickets を**部分文字列**（`"tickets/active" in path`）で判定する。したがって `os.path.join(cwd, 任意の語)` を無条件に適用すると、**cwd が `tickets/active` のとき任意の語が保護対象と判定される**。実測: `_is_guarded_path("tickets/active/NR>1 {print}")` は **True**。この性質が「cwd を全語に join する素朴な方式」を不可能にしている（§3-7・§3-8）。

### 3-4. L3: 構文レイヤ（第3版で「書き込み先オペランド」を概念として追加）

**「証拠があるときだけ deny する」を原則とする。** 判定順序（ステートメント単位）は第2版から不変:

① 出力リダイレクト（証拠ベース・ゲートなし） → ② heredoc（言及ゲートあり） → ③ 言及ゲート → ④ パイプ区間ごとのセグメント検査

①を先に置くことで `check_spec_structure.py … > docs/SPEC.md` が引き続き deny される（AC6）。

**第3版で追加する概念「書き込み先オペランド」:** 語のうち、**構文的に書き込み先と確定している**もの（出力リダイレクトの直後の語／`sort -o` の値／`uniq` の第2位置引数）だけを「書き込み先オペランド」と呼ぶ。cwd との結合（相対パスの解決）は**このオペランドに限って**行い、判定は単一のヘルパ `guarded_write_target(target, cwd, substs)` に集約する（§4-4(b)）。任意の語へ cwd を結合してはならない（§3-3 の帰結）。

**「書き込み先オペランドを取り出せない」書き込み形（awk のプログラム内リダイレクト・sed の `w`）は、オペランドを解決せず「構文の存在」で判定する**（AW-3・sed `w` 規則）。cwd が保護対象配下のときは、この構文が現れた時点で deny する（保護対象 cwd 下で書き込む awk/sed は、書き込み先が cwd 外であっても保守側に倒す。old=deny のため回帰にならない＝§2-1）。

### 3-5. degraded mode（第2版で確立・第3版で2点のみ追加）

発火条件5系統（未閉じ `'`／`"`／バッククォート／`$(`・`<(`・`>(`／**末尾の孤立エスケープ**）と、旧版の判定要素をすべて持つこと（P2）は第2版から不変。`don't` / `it's` 等の日常的な英文コメントで成立するため「稀な異常入力の受け皿」ではない。

**第3版の追加（2点）:**

1. **`degraded_violation(command, cwd="")`** — 呼び出し元 `find_violation` が持つ cwd を受け取り、ローカルの cwd 追跡の初期値にする（置換の内側が degraded になった場合にも cwd が効く）。

### 3-6. 設計判断（D1〜D7）

#### D1: awk の書き込み・実行経路は **本チケットのスコープに含める**（第3版で AW-4／AW-5 を追加し、規則の構造を「次元」で整理）

**理由（第2版から不変）:** (1) 旧版は `awk` が `ALLOWED_HEADS` に無く全 awk が deny だった。AC3 に従って追加した結果、awk の書き込み経路は**本チケットの変更が原因で新設された** false negative である。(2) `docs/SPEC.md` にはバックストップが無い。(3) AC を満たしたまま採れる代替が存在しない（awk 除外＝AC3 抵触／共起案＝AC2 抵触／先送り＝AC6 抵触）。

**規則を「次元」で整理する（第3版）。** awk が引数だけで書き込み／実行に至る経路は次の3次元に分かれる。第2版は③のみを見ていた。

| 次元 | 経路 | 規則 |
|---|---|---|
| ① オプション（書き出し） | `-o[FILE]`／`--pretty-print[=FILE]`、`-p[FILE]`／`--profile[=FILE]`、`-d[FILE]`／`--dump-variables[=FILE]` | **AW-4** |
| ② オプション（外部コード読み込み） | `-f FILE`／`--file=`（プログラム本体が不可視）、`-i FILE`／`--include=`（awk ソースライブラリ。**`inplace` が in-place 書き込み**＝C3）、`-l LIB`／`--load=`（動的拡張）、`-E FILE`／`--exec=`、`-D[FILE]`／`--debug[=FILE]` | **AW-4** |
| ③ プログラム内構文 | `print`／`printf` の `>` `>>` `\|` `\|&`、`cmd \| getline`、`system(…)`（＝C4）、`@load`／`@include` 指令、`ENVIRON` 経由の間接参照 | AW-1／AW-3／**AW-5** |
| （参考）変数束縛 | `-v NAME=VALUE`／`-vNAME=VALUE`／`--assign[=]`／位置引数 `NAME=VALUE` | AW-2 |

**規則一覧（AW-1〜AW-5）。** 先頭コマンドが `awk` のセグメントで、次のいずれかが成立すれば deny する。

| ID | 状態 | ゲート | 条件 |
|---|---|---|---|
| **AW-1** | 継続 | なし（証拠ベース） | 保護対象に言及する語が `>` または `\|` を含む |
| **AW-2** | 継続 | なし（証拠ベース） | awk 変数束縛の VALUE が保護対象に言及する |
| **AW-3** | ゲートを拡張 | **言及 or cwd 保護対象** | **文字列リテラル除去後**の語が `AWK_OUTPUT_RE`（`print`/`printf` の後、`;` `}` 改行に達する前に `>` `>>` `\|` が現れる）に一致 |
| **AW-4** | **新設（C3）** | **言及 or cwd 保護対象** | `-` で始まる語が `is_safe_awk_flag()`（既知の読み取り専用オプションのホワイトリスト）に一致**しない** |
| **AW-5** | **新設（C4）** | **言及 or cwd 保護対象** | **文字列リテラル除去前**の語が `AWK_EXEC_RE`（`\bsystem\s*\(` または `@load` / `@include`）に一致 |

**AW-4 をホワイトリスト（未知は deny）にする理由 — reviewer 提案の評価と採否:**

- reviewer 提案（AW-4 原案）は「語が `-i` / `-iVALUE` / `--include` / `--include=VALUE` に一致 → deny」というブラックリストだった。**方向は妥当だが不十分**である。同じ次元に `-f`／`-l`／`-E`／`-o`／`-p`／`-d`／`-D` が並んでおり、C3 を1つ塞いでも同型の穴が残る。実測でも `awk -f prog.awk tickets/active/APP-001.md`（プログラム不可視・束縛なし）は **old=deny → new=allow の未報告の同型回帰**である（AW-2 は束縛が無いと発火しない）。
- **オプションは man/`--help` で閉じた集合として列挙できる**唯一の次元であり、ホワイトリスト化の失敗方向は「安全なオプションの収載漏れ＝誤deny（可視・修正容易）」であって「危険なオプションの列挙漏れ＝黙ってすり抜け」ではない。**P4 の要求を満たす唯一の実装可能な形**である。
- `-i` を含む gawk のオプション群は読み取り用途でほぼ使われないため、`mentions_guarded or cwd_is_guarded` のゲートを前置すれば A-3a 系（`-F'\|'`）を壊さない（reviewer の評価と一致）。実測トレース: §4-5。
- 副作用として mawk/BWK awk 固有のオプション（`-W …` 等）は未収載のため保護対象に言及する場合 deny になる。**安全側であり、必要になれば安全性を確認してから収載する**（docstring に明記）。

**AW-5 の採否と評価対象:** reviewer 提案（`system\s*\(`）を**採用**し、`@load` / `@include`（gawk の拡張・ライブラリ読み込み指令）を追加する。評価は**文字列リテラル除去前**の語に対して行う（除去後より必ず広く一致する＝保守側。文字列内に `system(` が書かれているだけで deny になる誤denyは、`awk` が eval を持たない以上ごく稀であり許容する）。`cmd | getline` と `print |& "sh"` は **AW-1／AW-3 が既に捕捉済み**（reviewer 実測）であり追加規則を要しない。

**一般化（sed）:** `sed` の `w`／`W` コマンドと `-i` 全表記は第2版どおり維持し、第3版で **cwd 対応**にする（§3-8）。`sed -f SCRIPT`（プログラム不可視）と GNU sed の `e` フラグ（任意コマンド実行）は D4 のとおり**スコープ外**（old=allow）。

#### D6: スコープ判断の基準（第3版で新設・以後の判断をこの基準で行う）

C3／C4／H2 のような追加が繰り返されたため、「何を本チケットで閉じるか」の基準を明文化する。

1. **`old=deny → new=allow`（本チケットが開けた穴）は必ず閉じる。** 例外なし（AC6・SV-8 の「自分で穴を開けることは許容できない」原則）。
2. **`old=allow`（旧版から存在する穴）は原則スコープ外**（別チケット）。ただし次の2つは例外として含める。
   - (a) **1で作る機構が同時に閉じるもの**で、追加コストが数行かつ誤denyリスクが無いもの（例: `sort -o` の絶対パス形。cwd 相対形を閉じる機構が同じオペランド抽出であるため）。**「cwd 相対だけ deny・絶対パスは allow」のような説明不能な非対称を残さない**ことを優先する。
   - (b) **本 hook 自身が持つ閉じた列挙の誤り**（例: `FIND_WRITE_FLAGS` の `-fprint0` 欠落）。設計書が「網羅した」と主張している箇所の誤りは、主張ごと訂正する。
3. **脅威クラスの拡大（任意コマンド実行）や、`ALLOWED_HEADS`／`READONLY_SCRIPTS` の収載可否そのものを問う変更は、old=allow なら人間の判断を要する上位の設計変更**として扱い、本チケットに黙って混ぜない（GNU sed `e`・D7）。
4. 上記に該当しないものは §3-9 の棚卸し表・§6 のリスク・§10 の申し送りへ**必ず記載する**（黙って落とさない）。

#### D7: `is_readonly_script_call()` の許可経路偽装は **本チケットのスコープ外**（別チケットで即時起票を推奨）

**内容:** `python3 x=y .claude/skills/spec-interview/scripts/check_spec_structure.py docs/SPEC.md` が allow になるが、python3 が実際に実行するのは `x=y` という名前のファイルである。`IDENTIFIER=任意文字列` 形のファイルを用意できれば **READONLY_SCRIPTS の許可経路を偽装して任意コード実行に到達**でき、バックストップの無い `docs/SPEC.md` を含め本 hook を完全に迂回できる。

**スコープ外とする根拠（D6 の基準を適用）:**
1. **old=new=allow** — 旧版も同じ `re.fullmatch` で代入語をスキップしており、本チケットが開けた穴ではない（orchestrator・reviewer が独立検証済み）。
2. どの AC も要求していない。
3. **`READONLY_SCRIPTS` 許可経路の意味論を変える変更**であり、D6-3（脅威クラス・収載可否を問う変更）に該当する。人間は「設計デルタ → implementer」の運用を承認したが、**この脆弱性のスコープ拡張は明示的に承認していない**。
4. リトライ枠が残1のため、AC 外の変更でレビュー面を広げない。

**ただし implementer の逸脱4の理由付けは誤りであるため設計として訂正する（reviewer の指摘を反映）。** 実装メモは「`python3 FOO=bar script.py` のような形での挙動差を避けるための意図的な非統一」としているが、**その挙動差こそが脆弱性である**。したがって逸脱4は「安全・中立な判断」ではなく「**無償の修正を見送った判断**」として記録する。reviewer は `head_args()` へ寄せた版（`patched_guard.py`）を実測し、**5行の統一で偽装が deny になり、正規経路（`python3 {SCRIPT} docs/SPEC.md`・`FOO=bar python3 {SCRIPT} docs/SPEC.md`）は一切壊れない**ことを確認している。**別チケットでは、この5行の統一が第一候補の解**である。

**本チケットで行うこと:** §3-9 の棚卸し表に**未対応（深刻度 high・任意コード実行）**として明記／§6 R21 として記録／§10-1 の申し送り筆頭として起票を推奨／docstring の「既知の限界」に記載（Phase 7）。

### 3-8. cwd 追跡（第2版で新設・第3版で書き込み先オペランドの解決と伝播を追加）

**追跡（第2版から不変）:** `find_violation` はステートメントを左から右へ処理しながら `cwd`（追跡不能なら `None`）を持ち回る。`cd` セグメント自体は**常に allow**（AC3）で、更新後の cwd が保護対象なら以降のステートメントの**言及ゲートを無条件に真**とする。`cd` のオペランドが `$`・プレースホルダ・`~`・不在（`cd` / `cd -`）なら追跡打ち切り。

**第3版で追加する3点（H2 の修正本体）:**

1. **書き込み先オペランドの解決を単一ヘルパへ集約する。** `guarded_write_target(target, cwd, substs)` が「プレースホルダ解決 → `$`・未解決プレースホルダなら偽 → リテラルで保護対象なら真 → cwd が保護対象なら `normpath(join(cwd, target))` で判定」を担う。第2版で implementer が追加した `cwd_redirect_violation`（逸脱5・設計未記載の場当たり対応）を**この一般規則へ吸収して削除する**。呼び出し箇所は3つ（出力リダイレクト・`sort -o`・`uniq` 出力引数）＋degraded のリダイレクト走査。
2. **オペランドを取り出せない書き込み構文は「構文の存在」で判定する。** AW-3（awk の `print`/`printf` 出力リダイレクト）と sed の `w`／`W` は、cwd が保護対象なら**言及ゲート無しで**発火させる。これにより H2 の awk 4形・sed 2形が閉じる。**読み取り形（`{print $1}`・`NR>1 {print}`・`-F'\|'`・`sed -n '1,5p'`）は構文が一致しないため allow のまま**（§4-5 のトレースで確認）。
3. **置換再帰へ cwd を伝播する。** `find_violation` の置換再帰は現状ステートメント走査の**前**に一括で行われるため、`cd` 実行後の cwd を知らない。第3版では**置換をそれが出現したステートメントの評価時に、そのステートメントの cwd で再帰**させる（インデックス付きプレースホルダにより帰属が取れる＝P1 の副産物）。これで H2 の置換内3形が閉じる。

**フォールセーフ既定（P4-2）:** `CWD_SAFE_HEADS` に**明示収載されていない** head は、`cwd_is_guarded(cwd)` が真のとき deny する。現行の `ALLOWED_HEADS` 全 head は収載済み（根拠は §3-9 の「cwd 安全性」列）であり、**この規則は現時点では到達しない**。目的は「将来 `ALLOWED_HEADS` へ head を追加したとき、cwd 次元の棚卸しを忘れたら deny 側へ落ちる」という既定を持つことである（`op_kind` の到達不能な既定 `"sep"` と同じ性質の防御的既定であり、reviewer が第2版で「既定 `sep` は到達不能」を改善と評価した先例に倣う）。

**安全性:** 本機構は言及ゲートを真にする／書き込み先オペランドの解決範囲を広げる／未収載 head を deny する、のいずれも **allow → deny 方向にしか作用しない**。

**限界（docstring・README へ明記）:**
- `cd "$DIR"` / `cd $(…)` / `cd` / `cd -` は追跡できない（allow 方向）。
- **M5: `cd tickets/active && cd .. && rm active/APP-001.md`** のように、cwd と相対パスの**両方に接頭辞が分割**された形は閉じない（old=deny → new=allow の**未閉塞の限界**）。一般解は誤deny爆発を招くため実装せず、限界として明記する（reviewer 判定）。
- **M6: `cd tickets/active && mv /tmp/e APP-001.md` は allow（意図どおり）。** `mv` は CLAUDE.md が active/↔done/ の移動の正規手段と定めているため §3-9 で意図的に許可している。cwd 下でも同じ扱いとする。

### 3-10. 棚卸しの網羅根拠と維持手順（SV-7 への回答）

**SV-7 の指摘:** §3-9 は H1 の再発防止のために新設した機構（P3）だったが、その機構自体が同じ抜け方をした（`awk` 行に `-i inplace`・`system()` が無く、`cd` 行に相対パス書き込み全般が無い）。**したがって「表を書いた」ことは網羅の根拠にならない。**

**第3版が「網羅した」と主張できる根拠（3層）:**

1. **走査の方法を固定した。** 各 head について**4次元**（§3-9）を走査する。第2版の表は「引数だけで書ける／任意実行できる経路」という単一列で、次元が混在していたため「オプション次元」が丸ごと落ちた（C3・C4 はどちらもオプション次元／内部構文次元の別セル）。次元を列にしたことで**空白セルが可視になる**。
2. **根拠の出所を記録する。** 表の各セルは GNU gawk・GNU sed・GNU coreutils（`sort`・`uniq`・その他読み取り系）・GNU findutils・git のオプション仕様に基づく。**設計時点では man ページの実行確認を行っていないため、`awk` の安全オプション集合（`AWK_SAFE_FLAGS` / `AWK_SAFE_VALUE_FLAGS`）は Phase 6 の完了条件として実機の `awk --help` / `man` と突き合わせて検証する**（§4-9 **V-10**）。突き合わせの結果は「収載漏れ＝誤deny（可視・修正容易）」の方向にしか外れない（P4-1）。
3. **列挙が漏れても deny 側へ落ちる既定を持つ（P4）。** これが SV-7 への本質的な回答である。
   - **オプション次元**（C3 が属する次元）: `awk` はホワイトリスト。**未知のオプションは deny。** 新しい gawk オプションが追加されても、収載しない限りすり抜けない。
   - **cwd 次元**（H2 が属する次元）: `CWD_SAFE_HEADS` は明示列挙。**未収載 head は保護対象 cwd 下で deny。** `ALLOWED_HEADS` へ足すだけでは cwd 下の許可を得られない。
   - **採らなかった第2の防御:** 「保護対象に言及するセグメントで疑わしい構文を含めば deny」という包括規則は、AC1・AC2 に直接抵触するため採用しない（§3-7）。**したがってプログラム内構文の次元（C4 が属する次元）には機械的な既定が無く、ブラックリスト（AW-1／AW-3／AW-5）と表の維持に依存する。この1次元だけは残存リスクとして明示する**（§6 R23）。

**`ALLOWED_HEADS` に新コマンドを追加するときの手順（docstring と本節に同内容を置く）:**

1. `man <cmd>` / `<cmd> --help` を**4次元で走査**し、該当する経路をすべて洗い出す。判断に迷う経路は「危険」側に分類する。
2. §3-9 の表へ行を追加する（4列すべてを埋める。「なし」も明記する。空白セルを残さない）。
3. **cwd 安全性を判定する。** 「書き込み経路が無い」「書き込み判定がパスに依存しない（フラグ名・サブコマンド名で決まる）」「書き込み判定が cwd 対応済み」のいずれかを満たすときだけ `CWD_SAFE_HEADS` へ収載する。**満たさない／判定できない場合は収載しない**（保護対象 cwd 下で deny になる＝安全側）。
4. 新たに deny できるようになった形と、意図的に allow のままにする形の**両方**を `LEGACY_DENY_COMMANDS`（§4-7）と allow 固定テストへ追加する。
5. docstring の「既知の限界」を更新する。

```python
def segment_violation(words, substs=(), cwd=""):
    head = head_of(words)
    if not head:
        return None
    if SUBST_PLACEHOLDER_RE.search(head):
        return "コマンド名の位置にコマンド置換が使われています"
    if head in ("python3", "python") and is_readonly_script_call(words):
        return None
    if head not in ALLOWED_HEADS:
        return "'%s' は許可されていません" % head
    # フォールセーフ既定（P4-2・§3-8）。現行の ALLOWED_HEADS は全て収載済みの
    # ため到達しない。ALLOWED_HEADS へ追加したときに棚卸し忘れを deny 側へ倒す。
    if cwd_is_guarded(cwd) and head not in CWD_SAFE_HEADS:
        return ("保護対象ディレクトリを作業ディレクトリとする '%s' は"
                "許可されていません" % head)
    words = list(words)
    expanded = expand_all(words, substs)
    # 解決語では完全一致（--in-place 等）が壊れるため、raw と expanded の
    # 両方を評価する（M9・逸脱2 の設計反映。置換が無ければ従来と同一の1回評価）
    variants = [words] if expanded == words else [words, expanded]
    if head == "sed":
        flat = [t for variant in variants for t in variant]
        if any(SED_INPLACE_SHORT_RE.match(t) or t == "--in-place" or
               t.startswith("--in-place=") for t in flat):
            return "sed -i（in-place編集）は許可されていません"
        strict = cwd_is_guarded(cwd)
        if strict:
            # degraded は空白分割のため `w FILE` が2語に割れる。保護対象 cwd 下
            # に限り空白結合したテキストも評価する（§3-5）
            flat = flat + [" ".join(words)]
        if any(SED_WRITE_RE.search(t) for t in flat
               if strict or is_guarded_token(t)):
            return "sed の w コマンド（ファイル書き出し）は許可されていません"
    if head == "awk":
        for variant in variants:
            reason = awk_violation(variant, cwd)
            if reason:
                return reason
    if head == "sort":
        for operand in sort_output_operands(words):
            if guarded_write_target(operand, cwd, substs):
                return "sort の -o / --output（出力先指定）は許可されていません"
    if head == "uniq":
        if guarded_write_target(uniq_output_operand(words), cwd, substs):
            return "uniq の第2引数（出力ファイル）への書き込みは許可されていません"
    if head == "find" and any(t in FIND_WRITE_FLAGS for t in words):
        return "find の書き込み系フラグ（-exec/-delete等）は許可されていません"
    if head == "git":
        sub = next((t for t in head_args(words) if not t.startswith("-")), "")
        if sub not in ALLOWED_GIT_SUBCOMMANDS:
            return "git %s は許可されていません" % sub
    return None
```

```python
def is_safe_awk_flag(word):
    """awk のオプション語が「読み取りだけで完結する」既知の形か。

    **未知のオプションは False（deny 方向）へ倒す。** gawk の
    -f/-i/-l/-E/-D（外部プログラム・ライブラリ・拡張の読み込み）と
    -o/-p/-d（ファイルへの書き出し）はここへ載せないことで自動的に deny になる。
    収載を増やすときは man の説明にファイル書き込み・コード読み込みが無いことを
    根拠として記録すること。迷うオプションは収載しない。
    """
    if word in AWK_SAFE_FLAGS:
        return True
    for flag in AWK_SAFE_VALUE_FLAGS:
        if word == flag or word.startswith(flag + "="):
            return True
        if len(flag) == 2 and len(word) > 2 and word.startswith(flag):
            return True    # -FVALUE / -vNAME=VALUE / -eTEXT の結合形
    return False


def awk_violation(words, cwd=""):
    """awk セグメントの違反理由を返す（§3-6 D1 の AW-1〜AW-5）。"""
    # AW-1: 保護対象に言及する語そのものが > / | を含む（証拠ベース・ゲートなし）
    if any(">" in t or "|" in t for t in words if is_guarded_token(t)):
        return "awk のプログラム内リダイレクト（print > file 等）は許可されていません"
    # AW-2: 保護対象パスを awk 変数へ束縛している（証拠ベース・ゲートなし）
    if any(is_guarded_token(v) for v in awk_bindings(words)):
        return "awk の変数へ保護対象パスを束縛しています（-v / NAME=VALUE）"
    # 以降は「保護対象に言及する／保護対象を cwd とする awk」に限って適用する
    if not (mentions_guarded(words) or cwd_is_guarded(cwd)):
        return None
    for word in head_args(words):
        # AW-4: 未知・危険なオプション（外部コード読み込み／ファイル書き出し）
        if word.startswith("-") and not is_safe_awk_flag(word):
            return ("awk のオプション %s は許可されていません（外部プログラム・"
                    "拡張の読み込みとファイル書き出しの経路になりうるため）"
                    % display_text(word))
        # AW-5: system() / @load / @include（文字列リテラル除去前の語で判定）
        if AWK_EXEC_RE.search(word):
            return ("awk の system() / @load / @include（外部コマンド実行・"
                    "拡張読み込み）は許可されていません")
        # AW-3: print / printf の出力リダイレクト（文字列リテラル除去後で判定）
        if AWK_OUTPUT_RE.search(AWK_STRING_RE.sub('""', word)):
            return ("awk のプログラム内リダイレクト（print > file 等）は"
                    "許可されていません")
    return None
```

`awk_bindings` は現行のまま（`head_args` を使用。`--assign=NAME=VALUE` 対応済み＝M9・逸脱6）。

#### (e) `sort_output_operands` / `uniq_output_operand`（新規・§3-6 D4）

```python
def sort_output_operands(words):
    """sort の出力先を列挙する（-o FILE / -oFILE / --output FILE / --output=FILE）。"""
    operands, expect = [], False
    for word in head_args(words):
        if expect:
            expect = False
            operands.append(word)
            continue
        if word in SORT_OUTPUT_FLAGS:
            expect = True
        elif word.startswith("-o") and len(word) > 2:
            operands.append(word[2:])
        elif word.startswith("--output="):
            operands.append(word[len("--output="):])
    return operands


def uniq_output_operand(words):
    """uniq の第2位置引数（出力ファイル）を返す。無ければ空文字列。

    -f/-s/-w とその長形式は値を取るため、位置引数の数え方を誤ると
    `uniq -f 2 FILE` の `2` を第1位置引数と数えて FILE を出力先と誤認する。
    """
    positionals, expect = [], False
    for word in head_args(words):
        if expect:
            expect = False
        elif word in UNIQ_VALUE_FLAGS:
            expect = True
        elif word.startswith("-") and word != "-":
            continue                       # 結合形・その他のフラグ
        else:
            positionals.append(word)
    return positionals[1] if len(positionals) > 1 else ""
```

```python
def redirect_violation(statement, guarded_vars, substs=(), cwd=""):
    for index, (kind, value) in enumerate(statement):
        if kind != "op" or op_kind(value) != "redirect_out":
            continue
        if index + 1 >= len(statement):
            continue
        next_kind, target = statement[index + 1]
        if next_kind != "w":
            continue
        if "&" in value and (target.isdigit() or target == "-"):
            continue                                   # 2>&1 等の fd 複製
        resolved = expand_substs(target, substs)
        if (is_guarded_token(resolved) or
                any(n in guarded_vars for n in VAR_REF_RE.findall(resolved)) or
                guarded_write_target(target, cwd, substs)):
            return "リダイレクト（> %s）による書き込み" % display_text(target)
    return None
```

```python
def statement_violation(statement, guarded_vars, substs=(), cwd=""):
    """cwd は「このステートメントを実行する時点の作業ディレクトリ」（追跡不能なら
    None）。**第2版の疑似コードは cwd_guarded(bool) を渡していたが、実装は
    cwd 文字列を渡す。書き込み先オペランドの解決にパスが必要なため文字列が正。**"""
    reason = redirect_violation(statement, guarded_vars, substs, cwd)      # ①
    if reason:
        return reason
    words = [v for k, v in statement if k == "w"]
    if not (cwd_is_guarded(cwd) or mentions_guarded(expand_all(words, substs))):
        return None                                                       # ③
    if any(k == "op" and op_kind(v) == "heredoc" for k, v in statement):  # ②
        return "ヒアドキュメントによる書き込みの可能性"
    for segment_words in pipe_segments(statement):                        # ④
        reason = segment_violation(segment_words, substs, cwd)
        if reason:
            return reason
    return None
```

#### (h) `degraded_violation`（cwd を受け取り、`segment_violation` へ渡す）

```python
def degraded_violation(command, cwd=""):
    """字句解析できない入力向けのフォールバック（P2: 旧版の判定要素をすべて持つ）。
    新しい判定は segment_violation / awk_violation の内側にあるため、degraded は
    cwd を渡すだけで同じ保護を得る（判定ロジックを複製しない＝M10）。"""
    if not mentions_guarded(command.split()):
        return None
    for match in LEGACY_REDIRECT_RE.finditer(command):
        target = match.group(1)
        if target.startswith("&"):
            continue
        if is_guarded_token(target):
            return "リダイレクト（> %s）による書き込み" % target
    if "<<" in command:
        return "ヒアドキュメントによる書き込みの可能性"
    for statement in LEGACY_STATEMENT_RE.split(command):
        parts = [p for p in statement.split("|") if p.strip()]
        if not parts:
            continue
        words_list = [p.split() for p in parts]
        if cwd_is_guarded(cwd) or any(mentions_guarded(w) for w in words_list):
            for words in words_list:
                reason = segment_violation(words, cwd=cwd)
                if reason:
                    return reason
        for match in LEGACY_REDIRECT_RE.finditer(statement):
            if guarded_write_target(match.group(1), cwd):
                return ("リダイレクト（> %s）による書き込み" % match.group(1))
        cwd = next_cwd(words_list[0], cwd)
    return None
```

```python
def find_violation(command, depth=0, cwd=""):
    try:
        tokens, substs = lex(command)
    except ValueError:
        return degraded_violation(command, cwd)
    guarded_vars, seen = set(), set()
    for statement in split_statements(tokens):
        # 内側方向（置換の中身が書き込み）。**この文の cwd で評価する**ことで
        # `cd tickets/active && ls $(rm APP-001.md)` が閉じる。プレースホルダに
        # インデックスがあるため、どの置換がどの文に属するかが判る（P1 の副産物）
        for index in statement_subst_indexes(statement):
            seen.add(index)
            reason = subst_violation(substs, index, depth, cwd)
            if reason:
                return reason
        record_assignments(statement, guarded_vars, substs)
        reason = statement_violation(statement, guarded_vars, substs, cwd)
        if reason:
            return reason
        segments = pipe_segments(statement)
        cwd = next_cwd(segments[0] if segments else [], cwd)
    # どの文の語にも現れなかった置換（構造上起きないが、取りこぼしを作らない）。
    # cwd を与えず従来どおり評価する
    for index in sorted(set(range(len(substs))) - seen):
        reason = subst_violation(substs, index, depth, "")
        if reason:
            return reason
    return None


def statement_subst_indexes(statement):
    """ステートメントの語トークンに現れるプレースホルダのインデックスを返す。"""
    return [int(m.group(1)) for kind, value in statement if kind == "w"
            for m in SUBST_PLACEHOLDER_RE.finditer(value)]


def subst_violation(substs, index, depth, cwd):
    if index >= len(substs):
        return None                    # 利用者が書いた同名リテラル（R15）
    inner = substs[index]
    if depth >= MAX_SUBST_DEPTH:
        # 深追いはせず保守側で打ち切る（$($($(rm ...))) を抜け道にしないため）
        if is_guarded_token(inner) or cwd_is_guarded(cwd):
            return "深いコマンド置換の内側で保護対象パスに言及しています"
        return None
    return find_violation(inner, depth + 1, cwd)
```

`main()` は変更しない（`try/except Exception → allow()` の fail-open を維持）。

## 8. ロールバック戦略（第2版の実測に基づく。第3版で M1 無効化手順の記述を訂正）

**Phase 粒度の `git revert` は成立しない**（実測: Phase 1 は本体・テストの両方で CONFLICT、Phase 2 はテストで CONFLICT、Phase 3 のみ CLEAN）。Phase 4・6 は Phase 1・2 が書いた関数を直接書き換えるため、この性質はさらに強まる。**ロールバックの単位は「ブランチ全体」または「マージコミット」とする。**

```bash
# (a) 未マージ段階での全体破棄（orchestrator が実施。develop は無傷）
git worktree remove ../kenesis-loop-kit.wt/KLK-010
git branch -D fix/KLK-010-guard-bash-writes-shlex

# (b) develop へマージ後の取り消し（hook ファイル全体が旧版へ戻る）
git revert -m 1 {マージコミットのhash}

# (c) done 化後に問題が発覚した場合
# /rollback KLK-010   （done → implementation_done）
```

**規則単位で戻したい場合（誤denyが業務を止めている緊急時の一時措置）:** `git revert` ではなく**順方向の1点修正**を作る。
