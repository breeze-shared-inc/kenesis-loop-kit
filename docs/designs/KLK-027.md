## 3. 設計方針

**採用する方針:**

1. **AC1は「一本化」を採用する。② を書き手分担の正と定め、① を削除し、③ を②から導出される
   横断サマリと明示する。** ①（Required Output Format直下の括弧補記）はKLK-004設計書§4の
   共通テンプレートに存在しない追記であり、②の内容をその場で繰り返しているだけで独自情報を
   持たない。②（Ticket Integration／Git Rules）は実際の書き手手順を規定する一次情報であり、
   KLK-004設計書§4の文言と一致している。③（README.mdのwriter分担表）は4ロールを一覧できる
   利便性のために残すが、「②が正でありREADMEはその要約である」旨を明示する1文を追記する。
   これによりAC1の選択肢1（一本化）を採用しつつ、①削除によりRequired Output Formatの文言が
   KLK-004設計書§4の共通テンプレートと完全一致するようになる（これがAC3の機械検証対象になる）。
2. **①削除によって「代筆」という語がファイルから消えないよう、investigator.md/reviewer.mdの
   Ticket Integrationへ最小限の語を補う。** investigator.md/reviewer.mdは現状「代筆」という語を
   ①（削除対象）にしか持たない（Ticket Integrationは「書き出し」という表現のみ）。①をそのまま
   削除すると`tests/test_klk004_doc_wiring.py`の`test_ghost_write_roles_present_in_own_agent_files`
   （`assertIn("代筆", text)`、ファイル全文対象）が退行する。②を正とする方針と整合させるため、
   「書き出し」を「代筆で書き出し」に変える1語の挿入で「代筆」の語を②へ移し、既存テストを
   退行させずに①の重複を解消する（implementer.md/tester.mdは①が「自身が」であり②に既に
   「自ら」があるため、この追加調整は不要）。
3. **AC2は現状維持（防御的強化を見送る）。**
   `mentions_guarded`の3呼び出し箇所（`guard_bash_writes.py`内、`expanded_words`・
   `skeleton.split()`・`words_list`由来）はいずれも事前分割済みトークン列というKLK-010の契約を
   既に遵守しており、生文字列を渡す誤用は現存しない（investigator確認済み・§2参照）。
   `isinstance(values, str)`による防御的強化は現存しない誤用を修正するものではなく、独自の
   自動split実装を持ち込むことで既存tokenizerとの分割仕様の不一致という新たなリスクを生みうる。
   `test_mentions_guarded_raw_string_call_is_a_false_negative_trap`は「契約違反時にどうなるか」を
   固定した意図的な仕様テストとしてそのまま残す。コード変更は行わない。決定の経緯を将来の
   読み手に残すため、同テストの docstring に1文（本チケットでの決定）を追記する
   （動作は変えないドキュメンテーションのみの変更）。
4. **AC3は①削除後のRequired Output Format文言に対し、空白差異を無視した完全一致テストを
   追加する。** ①削除により investigator/implementer/tester/reviewer の4ファイルの
   Required Output Format文言は「`docs/reports/{ID}/{phase}.md`」というphase名の置換のみを
   許容するKLK-004設計書§4の共通テンプレートと意味的に完全一致する状態になる。改行位置の
   ワードラップ（investigator.mdのみ3行、他3ファイルは1行）はmarkdownの表示上の折返しであり
   内容の差ではないため、テストは空白（改行含む）を除去して比較する。architect.mdは
   意図的に異なる文言（既存のdocs/designs運用の明文化）であり対象外（既存テスト
   `test_architect_points_to_designs_not_reports`が既にこれを保証している）。
5. **AC4は人間決定(a)（2026-08-17 19:40、§10参照）を採用する。** publicプリセットでは
   `docs/reports/{ID}/`配下がIGNOREDに、`docs/reports/README.md`は常にNOT IGNOREDになることを
   `git check-ignore`の実行結果で固定する統合テストを追加する（KLK-026 AC5(b)の実態と一致させる）。
   privateプリセットでは同パスが常にNOT IGNOREDであることも対比として固定する。既存
   `tests/test_klk026_doc_wiring.py`の`TestGitignorePresetAsymmetry`は`.gitignore.public`/
   `.gitignore.private`の文字列としての存在確認のみであり、実際にgitの除外判定として機能するかは
   検証していない。`tests/test_metrics.py`の`TestRecorder`（サブプロセス実行パターン）を踏襲し、
   一時gitリポジトリを作成して`git check-ignore`を実行する統合テストとして追加する（§4-F）。
   テスト対象は`.gitignore.public`/`.gitignore.private`プリセットファイル自体であり、本リポジトリの
   実`.gitignore`の同期状態には依存しない設計とする（後述8.の同期作業とは独立）。
6. **AC5はrecord_metrics.pyの非衝突を「実際にhookスクリプトを起動して」検証する
   統合テストを追加する。** 既存の`is_ticket()`単体テスト（`tests/test_ticket_lib.py`）は
   関数の入出力のみを検証しており、record_metrics.py自身がそのゲートを正しく使って
   イベントを記録しないことまでは検証していない。`tests/test_metrics.py`の
   `TestRecorder`パターン（`_util.run_script`でサブプロセス実行→`self.events()`で
   `.metrics.jsonl`を検証）をそのまま踏襲し、`docs/reports/{ID}/{phase}.md`パスに対して
   イベントが記録されないことを確認する。frontmatterがチケットに酷似していても
   （`is_ticket()`のパス判定が先に効くことを示すため）除外されることを確認する
   adversarialケースを含める。
7. **AC6はポインタ書式定義の存在を、定義済みの2箇所（設計書とREADME）に対する
   軽量な部分一致テストで固定する。** 「詳細: docs/reports/{ID}/{phase}.md」という
   未置換プレースホルダのままの文字列は、実際の運用で埋められたポインタ（例:
   「詳細: docs/reports/KLK-025/investigation.md」）とは別に、docs/designs/KLK-004.md§4の
   pointer format定義とdocs/reports/README.mdの「ポインタの解決性」節の2箇所に
   リテラルで存在する。tickets/*.mdや過去のdocs/reports/{ID}/*.mdを対象にすると
   公開プリセットで追跡除外される場合にテストが環境依存になるため、常に追跡される
   定義ファイル2点のみを対象にする。
8. **本リポジトリ直下`.gitignore`の`.gitignore.public`同期を本チケットのスコープに含める
   （2026-08-17 19:40 人間決定）。** §2・§6で発見した「本リポジトリの実`.gitignore`が
   `.gitignore.public`の46-50行目（KLK-026が追加した`docs/reports/*/`ブロック）を含んでおらず、
   `docs/reports/{ID}/`が実際には現在も追跡され続けている」状態を、Phase1でリポジトリ直下
   `.gitignore`の末尾へ同ブロックを追記して解消する（§4-E）。対象は実ファイル`.gitignore`のみ、
   `.gitignore.public`/`.gitignore.private`プリセット自体は変更しない。既にコミット済みの
   `docs/reports/{ID}/*.md`は本追記後も追跡され続ける（gitignoreは新規ファイルにのみ効き、
   索引済みファイルの追跡解除には別途`git rm --cached`が必要だが本チケットでは行わない
   — §7参照）。

def make_repo_with_gitignore(gitignore_src):
    """一時gitリポジトリを作成しgitignore_srcの内容を.gitignoreとして配置する。
    呼び出し側がcleanup()すること。"""
    tmp = tempfile.TemporaryDirectory()
    cwd = tmp.name
    subprocess.run(["git", "init", "-q"], cwd=cwd, check=True)
    shutil.copyfile(gitignore_src, os.path.join(cwd, ".gitignore"))
    return tmp


def check_ignore(cwd, path):
    """git check-ignoreを実行し (is_ignored, returncode) を返す。
    rc=0: ignored, rc=1: not ignored。他のrcは実行時異常としてfailさせる。"""
    proc = subprocess.run(["git", "check-ignore", path],
                           cwd=cwd, capture_output=True, text=True)
    if proc.returncode not in (0, 1):
        raise AssertionError(
            "git check-ignoreが異常終了 (rc=%d): %s" % (proc.returncode, proc.stderr))
    return proc.returncode == 0, proc.returncode

## 8. ロールバック戦略

全ての変更が文言削除・1語挿入・1文追加・`.gitignore`への5行追記・新規テストファイルという
テキストレベルの変更のみで、hookロジック・状態機械には一切触れない。問題発生時はコミット
単位でrevertする。`.gitignore`追記のrevertは追跡状態を追記前に戻すのみで、既存の追跡済み
ファイルへの影響はない（§7）。

```bash
# developへマージ済みの場合
git revert <developへのマージコミットハッシュ>
```

Phase2（回帰テスト追加）のみを個別にrevertすると、Phase1の文言変更を検証する対象が
失われるため、Phase1とセットでrevertすることを推奨する（KLK-004・KLK-026と同型）。
