## 1. 目的

本チケットは `docs/SPEC.md` の要件ではなく、Kit自体（`.claude/hooks/guard_bash_writes.py`）のセキュリティ修正である（KLK-001〜013と同じ性質。spec_version「なし」の理由は上記フロントマター参照）。

`degraded_violation()`（字句解析に失敗した入力向けのフォールバック判定）は、コマンド置換（`$(...)`・バッククォート・プロセス置換）の境界を一切認識せず、単純な空白分割だけで判定する。そのため、コマンド置換の**内側**にある書き込み（`rm`・`sed -i`・`tee`等）は、外側の先頭コマンド（`ls`等）の単なる引数語として埋もれ、素通りする。末尾に ` #'`（未閉じの引用符を含むコメント）を1つ足すだけで、正常経路が正しく deny する形（`ls $(rm docs/SPEC.md)`）を丸ごと allow へ転じさせられる（H6。KLK-010 の最終レビューで検出され、C2・C8・H5 に続く「degraded に正常経路の能力が無い」4件目）。

本設計は、`degraded_violation()` に**閉じている**コマンド置換・バッククォート・プロセス置換の境界だけを機械的に抽出する専用のトレラント・スキャナを追加し、抽出した内側テキストを既存の `subst_violation`/`find_violation`（正常経路が既に持つ再帰評価機構）へ**そのまま**回す「案C」を採用する（詳細は §3）。

## 3. 設計方針

**採用する方針: 案C（置換境界の再帰評価。既存の `_skip_balanced`/`_skip_backtick`/`subst_violation` を再利用）**

`degraded_violation` の入口で、**閉じている**（＝正しく対応する終端が見つかる）`$(...)`／バッククォート／プロセス置換の境界だけを機械的に抽出し、`SUBST_PLACEHOLDER` に置き換えた「スケルトン」文字列と、抽出済みの内側テキスト一覧（`substs`）を作る新関数 `_extract_degraded_substs` を追加する。抽出した各置換は、正常経路の `find_violation` が行っているのと**同じ規律**（外側の言及ゲートより先に・ゲートに関わらず・その文の cwd で）で `subst_violation` へ回し、内側の違反を最優先で検出する。以降の判定（言及ゲート・リダイレクト・ステートメント分割・セグメント判定）は元の `command` の代わりに「スケルトン」に対して行う。

**この設計が成立する根拠（investigatorの実測を設計へ接続する）:**
- `_skip_balanced`／`_skip_backtick` は「開き括弧の次の位置」を渡すだけで独立に呼び出せる（`lex()` 自身がトップレベルで失敗する入力でも、**その手前まで進んだ部分**は正しく終端を見つけられる）。investigatorが実測済み
- `_take_subst`／`_take_backtick` はこれらを呼び、成功時は `substs` へ追加・`buf` へプレースホルダを積んで新しい走査位置を返す。**失敗時（終端が見つからない）は `ValueError` を送出する**ため、新関数はこれを `try/except` で捕捉し、「そこから先は原文のまま出力へ写して走査を打ち切る」（＝壊れている置換は**今までどおり**素の文字列として扱われ、既存の degraded 判定に委ねられる。何も失わない・保守側）
- 抽出した内側テキストは `subst_violation(substs, index, depth, cwd)` にそのまま渡せる。この関数は「正常経路 or degraded」を区別しない汎用の再帰入口であり、`MAX_SUBST_DEPTH` によるネスト打ち切りも変更せず継承する

**この設計で「置換が1つも無い入力ではスケルトンは command とバイト単位で同一になる」という不変条件が成り立つ:** `_extract_degraded_substs` は `$(`／`` ` ``／`<(`／`>(` に一致しない文字を1文字も変更せず出力へ写すだけの走査であるため、これらの記号を含まない入力（現行の degraded 系テスト20件超のうち `$(`／`` ` ``／`<(`／`>(` を含むものは C8 系の数件のみで、いずれも**外側の `lex()` は成功し** degraded_violation は**内側の already-degraded テキスト**でしか呼ばれない＝その内側テキスト自体にも通常 `$(`等は含まれない）に対しては、本変更後も `degraded_violation` の判定ロジックが読む文字列は変更前と1バイトも変わらない。これが AC2・AC4 の構造的な裏付けである（§4-6 で個々のケースを追跡済み）。

**採用しなかった代替案と却下理由:**

| 案 | 内容 | 却下理由 |
|---|---|---|
| **A: degradedへ落ちる入力自体を減らす**（`docs/designs/KLK-010.md` 申し送り11の1つ目） | `#` コメント本文を除去してから字句解析する、`shlex` に依存しない語分割にする等 | 大規模な変更で、**deny → allow 方向の変化を伴う**（申し送り10・R35で既に指摘済み。`cat a #> docs/SPEC.md` の old=deny な保護が失われる）。H6 単体の修正としては影響範囲が過大かつ既存設計原則（コメント本文は除去しない・§L0）と衝突する |
| **B: 置換記号を含む degraded 文を QT-1 同様「判定不能」として無条件 deny**（チケットの最小案） | `$(`／`` ` ``等を含む degraded ステートメントを、内容を評価せず、ゲート成立時に一律 deny | 実装は最小だが、**置換の中身を一切見ないため必要以上に広く deny する**。例えば `echo \`date +%Y\` tickets/active/APP-001.md #'`（読み取り専用の日常コマンドが何らかの理由で degraded に落ちた場合）のような**無害な置換**も一律 deny になり、案Cより誤deny面が広い。案Cは「内側が実際に書き込みか」を評価できるため、同じ安全性を**より狭い誤deny面**で達成できる。§6 に具体的な新規誤deny候補を列挙し比較した |
| **C（採用）: 置換境界の再帰評価** | 本節のとおり | — |

**案Bとの定量比較（誤deny面）:** 案Bは「degraded ＋ 置換記号を含む ＋ ゲート成立」の集合を**丸ごと** deny にする。案Cは同じ集合のうち「**置換の内側が実際に違反と判定されるもの**」だけを deny にする（内側が読み取り専用なら allow を維持）。したがって案Cの新規 deny 集合は案Bの新規 deny 集合の**部分集合**であり、案Cのほうが誤deny予算（AC3）に対して安全である。案Bを部分採用する理由は無いと判断した。

### 4-1. `_extract_degraded_substs` の実装

`degraded_violation` の直前に追加する。`lex()` の走査構造をなぞるが、次の3点だけが異なる:
1. 未閉じクォート・未閉じ括弧・末尾の孤立エスケープで例外を送出しない（`degraded_violation` はこれらの入力を扱うために呼ばれるため、ここで失敗すると何も抽出できなくなる）。閉じていない置換に出会った時点で**残りをそのまま出力へ写して走査を打ち切る**（それ以降の文字を1文字も変更しない＝既存の degraded の素朴な判定に委ねる）
2. 演算子をトークン化しない（`degraded_violation` は既存どおり空白分割・正規表現分割で処理するため、ここでは「置換かどうか」だけを判定する）
3. クォート文字自体を出力からはがさない（`shlex.split` 相当の脱クォートは行わない。既存の degraded 判定は脱クォートしていないため、脱クォートすると挙動が変わってしまう）

```python
def _extract_degraded_substs(command):
    """字句解析に失敗する入力からも、閉じているコマンド置換・バッククォート・
    プロセス置換の境界だけを機械的に抽出し、SUBST_PLACEHOLDER に置き換えた
    スケルトンと抽出済みの内側テキスト一覧を返す（H6 の修正本体）。

    lex() と異なり例外を送出しない。閉じていない置換（$( / ` の終端が
    見つからない）に出会った時点で、残りをそのまま出力へ写して走査を打ち切る
    （既存の degraded の素朴な判定へ委ねる＝保守側・何も失わない）。

    置換が1つも無い入力では、戻り値のスケルトンは command と**バイト単位で
    同一**になる（この関数のいずれの分岐も、$( / ` / <( / >( に一致しない
    文字を1文字も変更しないため）。
    """
    buf, substs = [], []
    i, n, quote = 0, len(command), ""
    while i < n:
        c = command[i]
        if quote == "'":
            buf.append(c)
            if c == "'":
                quote = ""
            i += 1
            continue
        if c == "\\" and i + 1 < n:
            buf.append(command[i:i + 2])
            i += 2
            continue
        if c == "$" and i + 1 < n and command[i + 1] == "(":
            try:
                i = _take_subst(command, i + 2, buf, substs)
            except ValueError:
                buf.append(command[i:])
                break
            continue
        if c == "`":
            try:
                i = _take_backtick(command, i + 1, buf, substs)
            except ValueError:
                buf.append(command[i:])
                break
            continue
        if quote == '"':
            buf.append(c)
            if c == '"':
                quote = ""
            i += 1
            continue
        # ---- ここから quote == ""（通常状態）専用 ----
        if c in "<>" and i + 1 < n and command[i + 1] == "(":
            try:
                i = _take_subst(command, i + 2, buf, substs)
            except ValueError:
                buf.append(command[i:])
                break
            continue
        if c == "'":
            buf.append(c)
            quote = "'"
            i += 1
            continue
        if c == '"':
            buf.append(c)
            quote = '"'
            i += 1
            continue
        buf.append(c)
        i += 1
    return "".join(buf), substs
```

**設計上の注意（implementerが変更してはならない点）:**
- `$(`／バッククォートの検出は `quote` が `""` でも `'"'` でも行う（bash はダブルクォート内でもコマンド置換を展開するため。`lex()` の `dq` 状態が `$(`／`` ` `` を扱うのと同じ）。**`<(`／`>(` の検出は `quote == ""` のときだけ行う**（プロセス置換はクォート内では展開されない。`lex()` の該当分岐が「通常状態」専用に置かれているのと同じ配置にすること）
- バックスラッシュの汎用エスケープ処理（`if c == "\\" and i + 1 < n:`）は `$(`／バッククォート検出より**前**に置く（さもないと `\'` を誤って引用符開始と解釈する）
- 末尾の孤立バックスラッシュ（`i + 1 == n`）はこの分岐にマッチせず、素通りしてそのまま `buf` へ1文字コピーされる（例外にしない。これは意図どおり）

```python
    機械的に抽出し、SUBST_PLACEHOLDER に置き換えたスケルトンを以降の判定へ
    渡す。抽出した各置換は**外側の言及ゲートに関わらず無条件に**（正常経路の
    find_violation のステートメントループと同じ規律で）subst_violation へ
    回し、内側で見つかった違反を最優先で返す。置換が1つも無い入力では
    スケルトンは command と同一であり、以降の判定ロジックは本修正の前後で
    1バイトも変わらない。
    """
    skeleton, substs = _extract_degraded_substs(command)

    # H6（内側方向）: 抽出した置換の中身を、それが現れる文の cwd で
    # 外側の言及ゲートより先に・ゲートに関わらず評価する。cwd 追跡は
    # このループで1回だけ確定し（stmt_cwds）、下の本体ループへ引き継ぐ
    # （cwd を2回独立に追跡して食い違わせないため）。
    stmt_cwds, running_cwd = [], cwd
    for statement in LEGACY_STATEMENT_RE.split(skeleton):
        stmt_cwds.append(running_cwd)
        indexes = sorted(set(int(m.group(1)) for m in
                              SUBST_PLACEHOLDER_RE.finditer(statement)))
        for index in indexes:
            reason = subst_violation(substs, index, depth, running_cwd)
            if reason:
                return reason
        parts = [p for p in statement.split("|") if p.strip()]
        if parts:
            running_cwd = next_cwd(parts[0].split(), running_cwd)

    # 以降は旧来の判定要素を skeleton に対して行う（既存ロジックを command
    # から skeleton へ差し替えただけで、他は無変更）。
    if not (cwd_is_guarded(cwd) or mentions_guarded(skeleton.split())):
        return None
    for match in LEGACY_REDIRECT_RE.finditer(skeleton):
        target = match.group(1)
        if target.startswith("&"):
            continue
        if is_guarded_token(target):
            return "リダイレクト（> %s）による書き込み" % target
    if "<<" in skeleton:
        return "ヒアドキュメントによる書き込みの可能性"
    for stmt_index, statement in enumerate(LEGACY_STATEMENT_RE.split(skeleton)):
        parts = [p for p in statement.split("|") if p.strip()]
        if not parts:
            continue
        words_list = [p.split() for p in parts]
        stmt_cwd = stmt_cwds[stmt_index]
        if cwd_is_guarded(stmt_cwd) or any(mentions_guarded(w) for w in words_list):
            if ANSI_QUOTE_RE.search(statement):
                return ANSI_QUOTE_REASON
            for words in words_list:
                reason = segment_violation(words, cwd=stmt_cwd, degraded=True)
                if reason:
                    return reason
        for match in LEGACY_REDIRECT_RE.finditer(statement):
            if guarded_write_target(match.group(1), stmt_cwd):
                return "リダイレクト（> %s）による書き込み" % match.group(1)
    return None
```

**この書き換えが既存ロジックを変えていないことの根拠:** `LEGACY_STATEMENT_RE.split(skeleton)` は **純関数**であり、同じ `skeleton` に対して1回目のループ（cwd 確定）と2回目のループ（`enumerate`）で**同一のリスト**を返す。したがって `stmt_cwds[stmt_index]` は、旧実装が2番目のループの**末尾**で `cwd = next_cwd(words_list[0], cwd)` と1文ずつ更新していたのと**完全に同じ値の列**になる（cwd の更新規則自体は1文字も変えていない。ループを「先に確定して配列に持つ」形へ再構成しただけ）。置換が無い入力では1番目のループの `subst_violation` 呼び出しは1度も発生せず（`indexes` が常に空集合）、2番目のループは旧実装とバイト単位で同じ `command`（＝`skeleton`）に対して同じ手順を踏む。
