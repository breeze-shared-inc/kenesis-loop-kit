## 3. 設計方針

**採用する方針（D1〜D7）**

### D1（AC1）: `is_ticket` は **cwd 非依存の純字句正規化（`os.path.normpath`）＋相対形の明示的許容**とする。`os.path.abspath` は採らない

`is_ticket` を「パス文字列だけで決まる純粋な述語」のまま保ち、`os.path.normpath` で `.` / `..` / 重複
スラッシュを畳んだうえで、`tickets/active/`・`tickets/done/` を **パスコンポーネント境界での一致**
（文字列先頭、または `/` の直後）として判定する。

**`abspath` 方式を却下した理由（investigator が指摘した cwd 依存のリスクへの対処）:**

- `abspath` は述語を**プロセスの cwd という隠れたグローバル状態**に依存させる。同じ引数に対して
  呼び出し環境で結論が変わる述語は、機械強制の基礎としても、テストの基礎としても不適切である。
- `abspath` が正しく働く前提は「hook プロセスの cwd＝チケットが実在するリポジトリのルート」であり、
  これは `docs/worktree-policy.md`「**チケット・メトリクスへの書き込みはメインworktree（orchestratorが動く場所）のみ**で行い、
  追加のworktreeはコード作業専用とする」という**運用上の約束**に依存する。運用ポリシーが破られたとき
  （別 worktree で hook が動く・`--add-dir` 経由・将来の外部ドライバ）に、述語は
  **黙って誤分類する**（別 worktree の `tickets/active/` を指してしまう＝偽陽性、あるいは実在しないパスを
  組み立てて偽陰性）。「文書化されていない前提を安全とみなさない」という原則（architect Never）に反する。
- そもそも `normpath` **単独では AC1 は解決しない**（`normpath("tickets/active/X.md")` は
  先頭スラッシュを付けないため `"/tickets/active/" in n` は依然 False）。「normpath 方式」を採るなら
  相対形の許容と**必ず対で**実装する必要がある。よって本設計は両者を組み合わせた1案として扱う。
- 副次的効果として `normpath` は**パストラバーサルの正規化**をもたらす。`x/../tickets/active/A.md` が
  正しく True になり（従来も True だが偶然）、`/repo/tickets/active/../../evil.md` は False になる
  （従来は誤って True＝チケットでないファイルへ検証をかけていた）。これは
  `guard_bash_writes.guarded_paths` が既に `os.path.normpath` を除外判定より先に適用しているのと
  **同じ理由**であり、Kit 内の正規化方針として一貫する。

**KLK-010 D2 との関係（統一しないことの再確認）:** 本変更後も両者は別基準のままである。
`_is_guarded_path` は「コマンド文字列の断片が保護対象に**言及**しているか」の再現率優先判定
（末尾スラッシュ不要・ディレクトリ指定や `SPEC.md` も拾う）であり、`is_ticket` は
「Write/Edit の対象ファイルが**状態検証対象の実チケットか**」の厳密判定（`.md` 必須・`_index.md` と
`Templates/` を除外）である。本設計が変えるのは**厳密判定の側の取りこぼし1点（相対形）だけ**で、
目的・影響半径の異なる統合は行わない。統一可否の再評価は KLK-020 が担う。

### D2（AC2）: 「status を伴わないイベント」を**チケット単位のイベント列から除外**してから集計する

`aggregate.main()` のチケットループ先頭で `evs` を **status イベントのみ**へ絞り込む。
status イベントの定義は `ev.get("type") != "retry_reset" and ev.get("to") is not None`
（AC2 が許す2条件の**論理積**。`retry_reset` は現時点で唯一の非 status イベントだが、
`to` の有無でも判定して将来のイベント種別追加に耐えるようにする）。

**「末尾が `retry_reset` なら単純に除外する」だけでは不足**する。進行中チケットに対する正当な
`retry_reset`（改善ループ・blocked 解消後の再挑戦）が末尾に来ると、現在ステータスを表示できなくなる。
本方式は「**直近の status イベントまで遡って `to` を採用する**」ことと等価であり、
進行中チケットは正しい status で「現在進行中」に表示される。

「経過」の基準時刻も**その status イベントの ts**（＝現在の status に入った時刻）とする。
`record_metrics.py` は遷移と `retry_reset` を**同一の `now`** で記録するため実運用で差は生じないが、
意味が「現在の status に入ってからの経過」で統一され、フェーズ滞留時間の定義とも一致する。

副次効果として**フェーズ別滞留時間の歪みも解消する**。従来は `retry_reset` が直前の遷移の「次イベント」
となり、同一 ts のため 0 秒の滞留が記録されていた。AC2 は in_progress 判定と後退遷移判定のみを
要求するが、同一根因であり同じ1行のフィルタで閉じるため一体で修正する（AC の緩和ではなく上乗せ）。
なお後退遷移判定は `frm in PHASE_ORDER and to in PHASE_ORDER` により**現状すでに実害が無い**が、
フィルタ適用によって AC2 が求める「除外」が構造として保証される。

### D3（AC1 の波及）: `tickets_dir_for` は**変更しない**

`tickets_dir_for` の戻り値は「ファイルを読み書きする実ディレクトリ」であり、判定用の文字列ではない。
相対形を受理して相対の `tickets` を返すようにすると、`record_metrics.py` が
**hook プロセスの cwd 依存の場所**へ `.metrics.jsonl` / `.metrics_state.json` を書きうる。
現行の「導出できなければ payload の `cwd` へフォールバックする」挙動（`        cwd = data.get("cwd") or os.getcwd()`）の
ほうが情報源として確実であるため、そちらを維持する。

結果として、相対パスで書き込まれたチケットに対しては
**サイドカー由来の prior（`state_record`）と in_progress 上限ゲート（`count_other_in_progress`）が
fail-open で無効化される**が、AC1 が要求する**スキーマ検証と状態遷移検証はファイル内容ベースの prior で
機能する**（従来は検証そのものが丸ごと飛んでいた＝厳密に改善）。この残存限界は §6 R10 に登録し、
`is_ticket` の docstring に明記して KLK-020 へ申し送る。

### D4（AC4）: コメント除去は**クォート状態を追跡する走査**で行い、`_unquote` の**前**に適用する

YAML の規則に合わせ、`#` がコメントを開始するのは「値の先頭」または「空白（半角スペース／タブ）の直後」に
現れ、かつ**クォートの外側**にある場合のみとする。**over-strip の防止**が最重要要件であり、次の3点で担保する。

1. クォート内の `#` は保持する（`title: "issue #123 fix"`）— 走査がクォート状態を持つため。
2. `#` の直前が空白でない場合は保持する（`title: C#` / `tags: [a#b]`）— YAML と同じ。
3. **クォートが閉じていない値では一切除去しない** — 走査がクォート状態のまま終端に達するので、
   自然に元の文字列を返す（追加の分岐は不要）。壊れた入力に対して「除去しすぎない」安全側へ倒れる。

`_unquote` の**前**に適用することで、investigator の追加発見（`title: "issue #123 fix" # trailing comment` で
`_unquote` が発火しない）も同じ規則で解消し、値は `issue #123 fix` になる。これは新しい仕様の追加ではなく
「コメントを正しく除去すれば `_unquote` の既存条件が満たされる」という自然な帰結であり、
**期待挙動としてテストで固定する**。

`if val == "":`（ネストマップを開く判定）は**コメント除去の後**に行う。これにより
`retry_counts: # コメント` が配下キーを取りこぼす不具合が閉じる。

### D5（AC5）: 5 hook に散らばる同一欠陥を、`_ticket_lib` の**共有ヘルパ1組**で構造的に閉じる

同じ2行を5ファイルへコピーするのではなく、`read_hook_payload()`（stdin から dict を読む。
不正 JSON・非 dict はいずれも `None`）と `as_dict(value)`（dict でなければ空 dict）を
`_ticket_lib.py` へ追加し、各 hook はこれを使う。README「設計方針: **単一の真実** — 検証ルールは
`_ticket_lib.py` に集約」に沿う。5ファイルとも同一の欠陥を持っていた事実が、点の修正ではなく
構造の一元化を要する根拠である。fail-open の**出口**（PreToolUse 系は `allow()`、
PostToolUse / Stop 系は `sys.exit(0)`）は hook ごとに異なるため、各 hook のローカルに残す。

**AC5 の適用範囲（同一関数・同一欠陥クラスの3層）:** 「非 dict 入力で AttributeError クラッシュしない」を
main() の入口で満たすため、次の3つを同じ規則で扱う。(b)(c) は AC5 の趣旨に含む拡張であり、
「外側だけ塞いで内側は素通り」という説明不能な非対称を残さないための措置である（AC の緩和ではない）。

- (a) payload そのものが非 dict（`[]` / `"x"` / `3` / `null`）→ fail-open
- (b) `tool_input` が非 dict → 空 dict として扱う
- (c) `file_path` / `command` / `cwd` が非 str → fail-open（`cwd` は `os.getcwd()` へフォールバック）

型の正規化は **hook 境界（main）で行い、判定関数（`is_ticket` / `is_spec`）は str を前提とする**という
レイヤ規約を置く（判定関数側にも型チェックを重ねると責務が二重になり、どちらが正か曖昧になる）。

**AC5 が依拠する前提（明示）:** 非 dict JSON で hook が rc=1 を返したとき、Claude Code の hook 実行契約上
それが「実際のブロック」になるのか「単なるエラー表示」に留まるのかは、**本リポジトリ外の仕様であり
確認できていない**（investigator Unknowns (b)）。本設計は**どちらであっても fail-open（allow）へ
明示的に落とすのが正しい**という前提を採る。根拠: 前者なら hook が正規の操作を妨げる（README
「fail-open: hook内部のエラーではループをブロックしない」に真っ向から反する最悪の結果）。後者でも
「検証が実行されなかったこと」が沈黙のうちに起きる＋観測ノイズになる。いずれの解釈でも
「明示的に allow して終わる」が改善であり、**前提が後日どちらに確定しても設計判断は変わらない**。

### D6（AC1 の副作用対策）: 相対パスの Write で**実体が見つからない場合は fail-open**

AC1 で `is_ticket` が相対形を受理すると、`validate_ticket_state.reconstruct` の Write 分岐が
`prior_text = read_file(path) if os.path.exists(path) else None` を通り、hook プロセスの cwd で解決できない
相対パスを「**新規作成**」と誤認する。その結果 `validate_transition(None, status)` が働き、
正当な更新が「新規チケットの初期 status は todo である必要があります」で **deny される**
（AC1 が新たな誤 deny を生む）。

対策として Write 分岐に「**パスが相対かつ実体が無いなら `ALLOW`**」を追加する。これは
「検知した違反のみ deny・推論による deny はしない」という hook の設計方針そのものである
（絶対パスで実体が無い場合は従来どおり新規作成として扱う。曖昧さが無いため）。
Edit 分岐は既に `if not os.path.exists(path): return ALLOW` を持つので変更不要。

### D7（AC3）: 時刻は **aware へ寄せて**正規化する（naive を落とすのではなく上げる）

`parse_ts` が naive な値を受けたらローカルタイムゾーンとみなして aware 化し（`dt.astimezone()`）、
aware はそのまま返す。`now` も `datetime.datetime.now().astimezone()` にする。
`record_metrics.py` が記録する ts は `datetime.datetime.now().isoformat(timespec="seconds")`＝
**naive なローカル時刻**であるため、「naive＝ローカル時刻」という解釈は現行の記録側と厳密に一致する。
aware 側を naive へ落とす案（tzinfo を捨てる）は、異なるタイムゾーンで記録された ts の**瞬間としての
順序を壊す**ため採らない。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| AC1 を `os.path.abspath(path)` で解決する | 述語がプロセス cwd に依存し、`docs/worktree-policy.md` の運用前提が破れたとき黙って誤分類する。テストも chdir 依存になる（D1） |
| AC1 を `os.path.normpath` **だけ**で解決する | `normpath` は先頭スラッシュを付けないため `tickets/active/X.md` は依然 False。単独では AC1 を満たさない（D1） |
| AC1 を各 hook の main() で `path = os.path.abspath(path)` と正規化する | 同じ規則が3〜4ファイルへ分散し、AC5 と同型の「同一欠陥が全ファイルに複製される」構造を再生産する |
| AC1 を機に `is_ticket` と `_is_guarded_path` を統一する | 人間承認済みスコープ決定に反する。KLK-010 D2（目的・スコープ・影響半径の3点）を覆すには再評価が必要で、それは KLK-020 の受け入れ条件 |
| AC2 を「末尾イベントが `retry_reset` なら1件だけ読み飛ばす」で解決する | 連続する `retry_reset` に弱く、また `retry_reset` が末尾に来た**進行中**チケットの現在ステータスを表示できない場合がある。イベント列のフィルタなら遡り回数に依存しない（D2） |
| AC2 を `in_progress` 判定だけの分岐（`if last_to is None: continue`）で解決する | done チケットは消えるが、**進行中チケットも消える**（現在ステータスの喪失）。AC2 の「done チケットが現在進行中に出ない」は満たすが観測性を損なう |
| AC3 を「`parse_ts` で aware を naive 化（tzinfo を捨てる）」で解決する | AC の許容範囲だが、異なる tz の ts が同一の壁時計として比較され順序が壊れる。aware へ寄せるほうが情報を失わない（D7） |
| AC3 で `"…Z"` 形式（UTC サフィックス）にも対応する | **本チケットでは行わない。** Python 3.11 未満の `fromisoformat` は `Z` を解析できないが、その場合 `parse_ts` は `None` を返すだけで**クラッシュしない**ため AC3 は満たされる。対応するとどのイベントが集計対象になるかが変わり、tz 正規化とは別の判断（記録側の形式変更の要否）を含む |
| AC4 を正規表現 `re.sub(r"\s+#.*$", "", val)` で解決する | クォート内の `#` を巻き込む（`title: "issue #123 fix"` が `title: "issue` に壊れる）。**現状すでに正しく動いている挙動を破壊する**ため不可（D4） |
| AC4 を「`#` を含む値はコメント除去しない」で回避する | `status: todo # 未着手` という AC4 の中心ケースが解決しない |
| AC5 を5ファイルへ `if not isinstance(data, dict): …` を個別に書く | 動作は同じだが、5ファイルに同一欠陥が複製されていた構造をそのまま温存する。次に入口の扱いを変えるとき再び5箇所の同期が必要になる（D5） |
| AC5 を `try` の内側で `raise` して既存 except に委ねる | 「妥当な JSON だが非 dict」を「パース失敗」として扱うことになり、意図が読めない。ログ・将来の分岐追加時に誤解を招く |

### 4-1. `_ticket_lib.is_ticket`（AC1）

`def is_ticket(path):` の本体を次の形へ置き換える。あわせて同ファイル内（`is_ticket` の直前）へ
純字句正規化ヘルパを追加する。ヘルパは**モジュール私有**（`_` 始まり）とし、KLK-020 が判定基準統一を
検討する際の共通化点として docstring に記す。

```python
def _normalize_path(path):
    """判定用のパス正規化（cwd 非依存の純字句正規化）。

    バックスラッシュ区切りをスラッシュへ寄せ、`.` / `..` / 重複スラッシュを畳む。
    相対形は相対のまま返す（os.path.abspath は使わない = プロセスの作業
    ディレクトリに依存させないため。docs/designs/KLK-012.md §3 D1）。
    """
    n = os.path.normpath(path.replace("\\", "/"))
    return n.replace("\\", "/")  # Windows の normpath が '/' を '\' へ戻すため


def _under_dir(n, marker):
    """正規化済みパス n が marker（例 "tickets/active/"）配下を指すか。
    先頭一致（相対形）と '/' 直後の一致（絶対形・サブパス）の両方を認める
    = パスコンポーネント境界での一致。'mytickets/active/X.md' は一致しない。"""
    return n.startswith(marker) or ("/" + marker) in n


def is_ticket(path):
    """path が状態検証対象の実チケット（tickets/active|done/*.md）か。

    テンプレート（/Templates/）とダッシュボード（_index.md）は対象外。
    パスは _normalize_path で正規化したうえで、絶対形と相対形（先頭スラッシュ
    無し）の双方を受け付ける（KLK-012 AC1）。

    guard_bash_writes.py 側の保護対象判定（_is_guarded_path / is_guarded_token）
    とは目的が異なるため基準は統一していない（KLK-010 D2。統一可否の再評価は
    KLK-020）。相対形のチケットパスでは tickets_dir_for が None を返すため、
    サイドカー由来の prior と in_progress ゲートは fail-open で効かない
    （KLK-012 §3 D3・§6 R10）。判定は str を前提とし、型の正規化は各 hook の
    main() 側で行う（KLK-012 §3 D5）。
    """
    n = _normalize_path(path)
    if "/Templates/" in n:
        return False
    if os.path.basename(n) == "_index.md":
        return False
    if not n.endswith(".md"):
        return False
    return _under_dir(n, "tickets/active/") or _under_dir(n, "tickets/done/")
```

補足: `Templates/` を先頭に持つ相対形（`Templates/x.md`）は最終条件を満たさないため、
`"/Templates/" in n` のままで取りこぼしは生じない（除外条件を増やさない）。

### 4-2. `_ticket_lib.parse_frontmatter`（AC4）

`def _unquote(value):` の直前へコメント除去ヘルパを追加する。

```python
def _strip_comment(value):
    """クォート外の `#` 以降をコメントとして除去する（YAML のコメント規則の近似）。

    `#` がコメントを開始するのは「値の先頭」または「空白（スペース/タブ）の
    直後」に現れ、かつクォートの外側にある場合のみ。クォート内の `#`
    （`title: "issue #123 fix"`）と、空白を伴わない `#`（`title: C#`）は保持する。
    クォートが閉じていない値では除去を行わない（除去しすぎ = 値の破壊を避ける
    安全側。走査がクォート状態のまま終端に達するので分岐は不要）。
    """
    quote = None
    for i, ch in enumerate(value):
        if quote is not None:
            if ch == quote:
                quote = None
        elif ch in ("'", '"'):
            quote = ch
        elif ch == "#" and (i == 0 or value[i - 1] in (" ", "\t")):
            return value[:i].rstrip()
    return value
```

`parse_frontmatter` の適用箇所は2つ。いずれも **`_strip_comment` → `_unquote` の順**で適用する。

1. ネストキー: `                data[current_map][key.strip()] = _unquote(val)` を
   `                data[current_map][key.strip()] = _unquote(_strip_comment(val.strip()))` にする。
2. トップレベル: `        if val == "":` の**直前**に `        val = _strip_comment(val)` を1行挿入する
   （`val = val.strip()` の後に位置する）。これにより `retry_counts: # コメント` が
   `val == ""` を満たしてネストマップを開き、`            data[key] = _unquote(val)` は
   コメント除去済みの値を受け取る（`            data[key] = _unquote(val)` 自体は変更不要）。

行頭コメント行（`raw.lstrip().startswith("#")`）のスキップは既存のまま変更しない。

def read_hook_payload(stream=None):
    """hook の stdin から JSON payload を dict として読む。

    JSON として不正な場合と、妥当な JSON だが dict でない場合（配列・文字列・
    数値・null）の両方で None を返す。呼び出し側は None を fail-open として
    扱う（PreToolUse 系は allow、PostToolUse / Stop 系は exit 0）。
    stream はテスト用（未指定なら sys.stdin）。
    """
    try:
        data = json.load(sys.stdin if stream is None else stream)
    except Exception:
        return None
    return data if isinstance(data, dict) else None


def as_dict(value):
    """dict ならそのまま、それ以外（None・配列・スカラー）は空 dict を返す。
    hook 入口で tool_input 等の型を正規化するために使う。"""
    return value if isinstance(value, dict) else {}

### 4-5. `aggregate.py`（AC2・AC3）

**(a) status イベントのフィルタ（AC2）** — モジュールへ述語を追加し、チケットループの先頭で `evs` を絞る。

を挿入する。ループ本体（dwell・後退遷移・blocked・done・`        last_to = evs[-1].get("to")`）は

**(b) tz 正規化（AC3）** — `def parse_ts(value):` の本体を置き換え、`    now = datetime.datetime.now()` を
`    now = datetime.datetime.now().astimezone()` にする。

```python
def parse_ts(value):
    """ISO8601 文字列を tz-aware な datetime として返す（解析不能なら None）。

    naive な値（record_metrics.py が記録する現行形式）はローカルタイムゾーンと
    みなして aware 化する。これにより tz-aware な ts が1件混入しても
    naive との減算で TypeError にならない（KLK-012 AC3・§3 D7）。
    """
    try:
        dt = datetime.datetime.fromisoformat(value)
    except Exception:
        return None
    return dt if dt.tzinfo is not None else dt.astimezone()
```
