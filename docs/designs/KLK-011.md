## 1. 目的

<!-- SPEC.mdの該当要件を必ずID(REQ-xxx / SCR-xxx / IF-xxx / EH-xxx / NFR-xxx)で明記し、この設計が何を解決するかを1〜3行で記述する -->

本チケットはKit自身の内部改善であり `docs/SPEC.md` は不在のため、対応する REQ / SCR / IF / EH / NFR-ID は存在しない（KLK-001〜010 と同じ前提）。要件の正はチケット KLK-011 の受け入れ条件（AC1〜AC6・§9に転記）である。

blocked中のチケット KLK-003 の設計書が他ファイルを**行番号**で参照しており、KLK-007・KLK-009 による行数変動でドリフトしている。とくに `CLAUDE.md` への「184行目の直後に1行追加」という**位置指定のみの操作**は、字面どおり適用するとポリシー管理表の途中へ誤挿入される。本設計は (1) `docs/designs/KLK-003.md` の全参照を「節見出し＋一意な引用文字列」形式へ書き換え、(2) 再発防止として `docs/designs/_TEMPLATE.md` に参照ルールを追加し、(3) KLK-009 起因の `CLAUDE.md` ポリシー管理表の精度低下を最小修正で補正する。

## 3. 設計方針

**採用する方針:**

1. **KLK-003.md は検出された12行すべてを書き換える（AC1の「少なくとも」を全件適用と解釈）。** ズレている3論点だけを直すと、残り9箇所は「今は偶然一致しているだけの時限爆弾」として残り、次に被参照ファイルが編集された瞬間に同じ事故が再発する。チケット「関連」の `教訓の自己適用: 本チケットの受け入れ条件・設計でも行番号でなくシンボル名/節見出しで参照すること` とも整合する。全件書き換えは「行番号参照0件」という**二値で機械検証できる状態**を作れる点でも優れる（部分是正では「残り9箇所は正しい行番号か」を毎回人手で確かめる必要が残る）。

2. **参照形式を「対象ファイルパス＋節見出し（またはシンボル名）＋一意な引用文字列」に統一する。** 引用文字列は implementer が Edit の `old_string` にそのまま使える粒度で書く。引用文字列が対象ファイル内で一意でない場合（例: `except Exception:` は `validate_ticket_state.py` に4回出現）は、それを含む一意なシンボル（`def count_other_in_progress(path):`）とセットで示し、単独のアンカーとしては使わない。

3. **「位置指定のみの操作」を Edit の old_string アンカーへ変換する（本チケット最大の実害の解消）。** `CLAUDE.md` への1行追加は「N行目の直後」ではなく「ポリシー管理表の最終行そのものを old_string に与え、`表最終行＋改行＋追加行` を new_string にする」方式へ書き換える。これにより挿入位置がファイル内容側に固定され、行数変動から独立する。アンカー `| CLAUDE.md＝インデックス＋共通定義の維持 | 本ファイル ポリシー管理の原則（再肥大化の防止） | CLAUDE.mdを編集する人間 / Claude | - |` は本チケットの CLAUDE.md 変更（§4-3）でも変更されないため、KLK-003 再開時にそのまま使える。

4. **再発防止ルールは `docs/designs/_TEMPLATE.md` の §2「関連する既存ファイル」直下に HTMLコメントとして置く。** 理由:
   - **手段の一貫性** — テンプレート内の規律はすべてHTMLコメントで表現されている（§1のID明記、§4のシークレット禁止・実装Phaseの規律）。CLAUDE.md ポリシー管理表も `designs/_TEMPLATE.md §1コメント` / `§4「実装Phase」コメント` という形で**コメントを正として参照している**ため、同じ手段を採ることでポリシーの置き場所が一貫する。
   - **成果物を汚さない** — HTMLコメントは architect がテンプレートをコピーして設計を書く際に消費され、完成した設計書には残らない運用が既に定着している（`docs/designs/KLK-003.md` にはHTMLコメントが1つも残っていない）。冒頭ブロッククォートに書くと全設計書に本文として複製され、読者向けでない作業ルールがノイズとして残る。
   - **密度が最も高い場所** — ドリフトが実際に発生したのは §2 の「関連する既存ファイル」リストである。ただしルール文面自体には「§2に限らず本設計書の全節に適用する」と明記し、§3・§4・§6・§9 での参照も対象に含める（KLK-003.md では12行のうち8行が§2以外にあった）。
   - `docs/designs/README.md` には参照形式に関する記載がなく（`## 運用ルール` はファイル分割・上書き・Gitヒストリの運用のみ）、**重複・矛盾は生じない**。README は「設計書のライフサイクル運用」、_TEMPLATE.md のコメントは「設計書の書き方」という責務分担が保たれる。

5. **CLAUDE.md は既存3行のセル文言修正のみ。行の追加・削除も本文セクションの追加も行わない。** 「再肥大化の防止（構造維持の原則）」を崩さないためであり、`git diff -U0 -- CLAUDE.md` の増減が3行の置換（+3/-3）に収まることを機械検証条件にする（§4-5 V3）。(c) の補正は「各」という全称表現の除去に限定し、`orchestrator.md` へ `## Model Assignment` 節を新設することはしない（agents/*.md の編集は本チケットのACの範囲外であり、`orchestrator.md` は冒頭ブロッククォート `**実行形態の注意:**` のとおりメインスレッドとして実行されサブエージェントとして起動されないため、frontmatter による model 指定の対象になるかの判断自体が別論点である。§6に将来の改善候補として記録する）。

6. **検証は grep ベースの機械チェックに落とす（AC5）。** 「参照先がすべて実在し、リンク切れ・行番号ズレが解消されている」を tester が再現できるよう、(V1) 行番号参照0件の検出、(V2) 全アンカーの現存・一意（`grep -c` が1）、(V3) CLAUDE.md 補正の前後確認、(V4) テンプレート追記と README 非重複、(V5) 既存テスト293件、に分解する（§4-5）。**検証コマンドには `tickets/active` / `tickets/done` / `SPEC.md` というリテラルを含めない** — `.claude/hooks/guard_bash_writes.py` の `def mentions_guarded(command):` が `command.split()` の各トークンを `def is_guarded_token(token):` に渡して部分文字列判定するため、grep のパターン側にこれらの文字列があるだけでガード経路に入り、KLK-010（`guard_bash_writesの誤denyとすり抜け解消（字句解析のshlex化）`）で扱われている誤denyを踏むおそれがある。該当箇所は `tickets.active.` のように正規表現のワイルドカードで書くか、部分一致に短縮して回避する。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| ズレている3論点だけを是正し、残り9箇所は行番号のまま最新値に更新する | 「今は偶然一致している」状態を維持するだけで、次の被参照ファイル編集で同じ事故が再発する。機械検証も二値にならず、毎回人手照合が必要になる。チケット「関連」の教訓の自己適用にも反する |
| 参照ルールを `docs/designs/README.md` に書く | READMEは設計書の**ライフサイクル運用**（分割管理・上書き・Gitヒストリ）を扱う人間向け文書で、architectが設計を書く瞬間には読まれない。テンプレートのコメントに置くほうが「書く直前に必ず目に入る」ため実効性が高い。またCLAUDE.mdポリシー表の既存慣行（`designs/_TEMPLATE.md §1コメント` を正として参照）とも整合しない |
| 参照ルールを `_TEMPLATE.md` 冒頭のブロッククォートに書く | ブロッククォートは設計書にそのまま複製され読者に提示される部分であり、architect向けの作業ルールを混ぜると全設計書にノイズが残る。HTMLコメント方式なら成果物に残らない |
| 参照ルールを `.claude/agents/architect.md` に書く | AC2が `_TEMPLATE.md` への追加を要求しており、ACを満たさない。加えて agents/*.md は KLK-009 で軽量化した直後であり、テンプレート側で足りるルールを行動規範へ増やすのは肥大化方向 |
| CLAUDE.md ポリシー表の該当行に `tests/test_agent_frontmatter.py`（`SONNET_ASSIGNED` / `NO_MODEL_KEY` による機械強制）を転記先として追記する | 表の精度は上がるが、AC3が挙げる3件の不正確さの是正ではなく**新規の情報追加**であり、「変更は最小限のセル文言修正に留める」という制約から外れる。§6に将来の改善候補として記録する |
| 「同一フェーズ並行1件」を orchestrator.md へ規約として復元する | 人間が「転記漏れによる形骸ラベルであり、復活させずセル・行名から除去する」と決定済み（チケットのログ 2026-08-14 11:48）。設計でこれを覆さない |
| `docs/designs/` 配下の**全**設計書（KLK-001/002/004/007/009 にも行番号参照が残る）を一括是正する | AC1のスコープは `docs/designs/KLK-003.md`。done済みチケットの設計書は当時の記録であり、書き換えると「その時点の設計」というGit上の記録価値を損なう。in-flightチケットの設計書に限った是正が妥当（§6に観測結果を記録） |
| 行番号参照を禁止する機械チェック（hook / テスト）を新設する | AC2はテンプレートへのルール追加を求めており、hook追加は範囲外。導入するなら被参照ファイル側の変更検知まで含めた設計が必要で、独立チケット相当の規模になる（§6に将来の改善候補として記録） |
