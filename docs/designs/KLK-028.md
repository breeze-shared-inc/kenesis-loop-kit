## 3. 設計方針

**採用する方針（D1〜D3）**

### D1（AC1）: ネストマップは**確定を遅延**させ、子行が1件も来なければ `None` にする（`{}` を正としない）

「コメントの有無」ではなく「**実際に子行が来たかどうか**」だけを唯一の判定基準にする。これはYAMLの
実際の意味論（`yaml.safe_load` は `title:` も `title: # comment` も、後続に子要素が無ければ両方
`None` を返す。investigatorがPyYAML 6.0.1で実測済み）と正確に一致する。

具体的には、`if val == "": data[key] = {}; current_map = key` で**楽観的に**マップを開く既存の
仕組みは変えない（`retry_counts: # コメント` の直後に子行が続く現状のケースをそのまま通すため）。
これに加えて、**現在開いているマップの外へ出るタイミング**（次の非インデント行に到達したとき、また
frontmatter終端に到達したとき）で、そのマップが**一度も子行を受け取っていなければ**（`data[current_map]`
が空の `{}` のまま）、`None` へ差し替える。

- `retry_counts: # コメント` の直後に3つの子行が続く（既存ケース）→ マップの外へ出るまでに
  `data["retry_counts"]` は非空になっている → 差し替えは発生せず、辞書のまま（**回帰なし**）
- `title: # コメント` の直後に子行が続かない（AC1の中心ケース）→ 次の非インデント行（または終端）に
  達した時点で `data["title"]` は空の `{}` → `None` へ差し替える
- コメントの有無は無関係。`title:`（コメントなし・値が空）も同じ理由で `None` になる（YAMLとの
  一致がより強まる。既存の空行スキップ・行頭コメントスキップの挙動は変更しない）

**`{}` を正とする案を却下する理由:** 現状の `{}` は「実際にはスカラー（あるいは値なし）だったキーが、
辞書型として下流へ渡る」という型の誤りを固定してしまう。`validate_schema` は「キーの存在」しか見ない
ため deny 方向の安全側には働くが、`state_record` のように `.get("id")` の返り値を素通しで使う箇所
（KLK-012 D5のレイヤ規約に沿えば、判定関数側は型を前提にできる）にとって、`{}` と `None` はいずれも
falsy であり後方互換上の実害の差は無い。両者に実害の差が無い以上、**YAMLの実際の意味論に一致する側**
を採る方が「文書化されていない挙動を安全とみなさない」という原則に沿う。

**空文字列（`""`）を正とする案を却下する理由:** KLK-012前の推定挙動（investigatorが近似再現した
`{'title': '# コメント'}` に近い、コメント込みの文字列保持）でも、YAML準拠（`None`）でもない
第三の値であり、どちらの参照点とも一致しない。採る理由が無い。

### D2（AC2）: ヘッダの「イベント数／チケット数」を**本文集計対象（statusイベントを持つチケット）に
一致**させる。不整合を残したまま出力上明示する案は採らない

`aggregate.main()` のチケットループ内で、`is_status_event` フィルタ後に `evs` が空でなかった
（＝本文の各セクションに実際に登場する）チケットについてのみ、そのチケットのフィルタ後イベント数を
加算した2つのカウンタ（チケット数・イベント数）を導入し、ヘッダはこの値を使う。

**「不整合を出力上明示する」案を却下する理由:** 「フィルタ前 N件（うち retry_reset のみ M件）」のような
新しい表示規約を追加すると、`/metrics` の出力形式が1箇所だけ複雑になり、他のセクションとの一貫性
（priorities「Clear boundaries」）を損なう。`/metrics` は人間向けの観測ツールであり、hookの
deny/allow判定には使われない（KLK-012 review M4の評価どおり）ため、ヘッダを本文の集計基準に厳密に
合わせることが最も単純で誤解の余地が無い。生カウント（`len(events)` / `len(by_ticket)`）を別途知る
必要が生じた場合は、別の観測手段（`tickets/.metrics.jsonl` を直接 `wc -l` する等）で足り、
`/metrics` の出力契約を複雑化させる理由にはならない。

### D3（AC3・AC4）: `reconstruct` のWrite分岐は**変更しない**。Missing Testsはテスト追加のみで解消する

`.claude/hooks/validate_ticket_state.py` の `reconstruct` は、KLK-012 D6の設計のとおり
`os.path.exists(path)` → `os.path.isabs(path)` の順序で**既に正しく実装されている**
（investigatorが実測確認済み。KLK-012 reviewer・investigatorのいずれも「現在の不具合ではない」と
明記）。AC3・AC4は「正しい実装を将来の変更から守るテストが無い」ことが課題であり、実装を変更する
理由が無い。**テストの追加のみ**で受け入れ条件を満たす。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| AC1: `{}` を正としてテストで固定する | D1で述べたとおり、YAML意味論と食い違う型の誤りを仕様として固定することになる。KLK-012 D4がYAML準拠方向（R2のover-strip許容）に倒した判断と整合しない |
| AC1: 空文字列 `""` を正とする | KLK-012前推定・YAML準拠のいずれとも一致しない第三の値であり採る理由が無い（D1） |
| AC1: 「コメントを含む行」と「コメントを含まない空値行」を別ルールにする（コメント行だけ`None`、無コメントの空値`title:`は`{}`のまま） | 子行の有無という単一の構造的基準から外れ、同じ「後続に子行が無い」状況に対して見た目（コメントの有無）で異なる型を返す一貫性の無いAPIになる。AC1が問うているのは「コメントの有無で意味を変えるべきか」であり、YAMLはコメントの有無で意味を変えない |
| AC2: ヘッダに「フィルタ前/フィルタ後」の2系統の数値を併記する | 出力形式が複雑化し、他セクションとの一貫性を損なう。判定に使わない観測ツールの出力契約を複雑にする理由が無い（D2） |
| AC3・AC4: `reconstruct` にコメントや assert を追加して順序を明示する | 実装は既に正しく、順序への依存を実行時に検証する手段（テスト）が課題の中心。コード側の追加は目的を達成しない（D3） |

### 4-1. `_ticket_lib.parse_frontmatter`（AC1）

`def parse_frontmatter(text):` 内、トップレベル分岐の直前（`        current_map = None` の直後、
`        if ":" not in raw:` の手前）で、**次の非インデント行に入る前に現在の `current_map` を
確定させる**処理を追加する。引用文字列（現状。一意）:

```
        current_map = None
        if ":" not in raw:
            continue
```

これを次に置き換える（`current_map = None` の**前**に確定処理を挿入する。順序が重要:
確定はリセットの前に行う必要がある）:

```python
        if current_map is not None and not data[current_map]:
            data[current_map] = None  # 子行が1件も来なかった＝スカラーの空値（KLK-028 AC1）
        current_map = None
        if ":" not in raw:
            continue
```

さらに、frontmatter終端で `current_map` が開いたまま（最終行が空値行だった場合）のケースを閉じるため、
`return data` の直前に同じ確定処理を追加する。引用文字列（現状。一意）:

```
            data[key] = _unquote(val)
    return data
```

これを次に置き換える:

```python
            data[key] = _unquote(val)
    if current_map is not None and not data[current_map]:
        data[current_map] = None
    return data
```

**影響を受けない既存パス:** インデント行の処理（`current_map is not None and ":" in raw` の分岐、
`data[current_map][key.strip()] = ...`）と、空行・行頭コメント行の `continue`（`current_map` を
リセットしない既存の仕組み。investigatorが確認した「空行を挟んでも子行の取り込みが継続する」挙動）は
**一切変更しない**。子行が実際に来た場合は `data[current_map]` が非空になるため、上記の確定処理は
「非空チェック」で素通りし、辞書のまま残る。

### 4-3. `tests/test_ticket_lib.py`（AC1）

### 4-4. `tests/test_metrics.py`（AC2）

`class TestAggregate(unittest.TestCase):` 内、`def test_retry_reset_only_ticket_survives(self):`
メソッドの末尾（`# --- KLK-012 AC3: tz-aware な ts が混入しても完走する ---` の手前）へ次のテストを
追加する。

```python

    def test_header_counts_exclude_retry_reset_only_ticket(self):
        # investigatorの実測repro: APP-001(created→todo) + APP-050(retry_resetのみ)
        # ヘッダは本文と同じ「1チケット・1イベント」を示すべき（従来は2/2）

        self.assertIn("イベント数: 1 / チケット数: 1", out)

    def test_header_zero_when_all_tickets_retry_reset_only(self):

        # （フィルタ前の生カウントに戻ってしまう不整合を明示的に禁止する）
```
