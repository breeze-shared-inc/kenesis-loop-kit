## 1. 目的

`guard_bash_writes.py` の `sed` スクリプト引数判定（`SED_WRITE_RE`）はアドレス前置き（`1w`／`$w`等）と`/`以外の区切り文字（`s#a#XYZ#w`等）を取りこぼし、実機GNU sedで保護対象の上書きを許してしまう（KLK-010 H7・investigator新規発見）。人間承認済み方針（2026-08-17）に基づき、awkのAW-7（`docs/designs/KLK-010.md` §3-6 D8）と同型の「プログラム本文のホワイトリスト」を`sed`へ新設し、`w`／`W`の取りこぼしを構造的に閉じるとともに、副次効果として`s///e`・`e`コマンド（KLK-010 D6-3でスコープ外とした穴）も自動的にdenyへ落とす。対応するチケット受け入れ条件はAC1〜AC9（本書冒頭表）。

## 2. 現状

**現在のフロー:**
```
segment_violation(words, substs, cwd, degraded)
  └─ head == "sed" の分岐
       ① SED_INPLACE_SHORT_RE / --in-place で -i 系を deny（無条件）
       ② SED_WRITE_RE をスクリプト引数へ適用（正常経路・degraded経路の区別なし）
            - 対象: strict(cwd guarded) なら全トークン＋空白結合テキスト、
                    そうでなければ is_guarded_token(t) が真のトークンのみ
            - SED_WRITE_RE = r"(?:^|[;{}\s/])[wW]\s+\S"
              → w/W の直前が ';{}' 空白 '/' 以外（アドレス構文・s/yの
                非'/'区切り文字）だと不一致＝allowへ素通りする
       ③ s///e・eコマンド・-f SCRIPT に対応する判定コードは無い
        （KLK-010 D6-3・INV-SED-05〜07でallow登録済みの既知の穴）
```

**問題の所在（investigator報告・実機GNU sed 4.9で確認済み）:**
- `SED_WRITE_RE`は`w`/`W`の直前文字を`;{}`空白`/`に限定しているため、アドレス前置き（数字・`$`・`,`・`!`・`~`）や`s`/`y`の非`/`区切り文字（`#`・`,`・`\|`等）の直後にある`w`/`W`を検出できない。
- この判定は正常経路・degraded経路のどちらでも同一コードを通る（awkの`AW-7`が`degraded`引数で正常経路のみに限定しているのと異なり、sedは区別が無い）。

## 3. 設計方針

**採用する方針: SED-7（sedプログラム本文のホワイトリスト。AW-7と同型・KLK-010 §3-6 D8を参照）**

awkのAW-7は3条件（許可文字集合／呼び出し名の許可集合／出力構文の順序条件）で構成されるが、sedへ同型適用する際、investigatorがEvidenceで指摘した6論点（区切り文字の任意性／アドレス構文の列挙／GNU拡張と移植性／`{}`グルーピング等の合成／`r`/`R`コマンド／`s///e`と`e`コマンドの扱い）を検討した結果、次の**構造的な簡略化**が成立する。

1. **「呼び出し名の許可集合」（条件2）は「許可文字集合」（条件1）へ吸収される。** sedのコマンドは`p`・`d`・`s`等の**単一文字**であり、awkの`IDENT(`のような複数文字の識別子抽出が不要。安全なコマンド文字の集合を1つ定義すれば、それがそのまま「呼び出し名の許可集合」を兼ねる。
2. **「アドレス構文の列挙」（investigator論点2）は個別の文法規則として列挙する必要がない。** アドレスを構成する文字（行番号の数字・`$`・`,`・`!`・`~`・`+`）を安全文字集合へ加えるだけで、`1,2w`・`2!w`・`0~2w`・`3,+5p`等のあらゆる組み合わせが自然に扱える（個々のアドレス文法を正規表現で列挙する必要がない）。
3. **「出力構文の順序条件」（条件3）は不要である。** awkは`print`の**後**に`>`が来る場合のみdenyという順序依存の判定を要するが、sedには「安全な位置」と「危険な位置」の区別がない——`w`／`W`／`r`／`R`／`e`は構造上どこに現れても書き込み・情報開示・任意コマンド実行の経路になる。**除去されなかったテキストにこれらの文字が1つでも残っていれば、位置に関わらず無条件にdenyしてよい**（KLK-010 P8: 除去は allow 方向にのみ働く危険な操作であり、除去しない判断は常に安全側）。
4. **区切り文字の任意性（investigator論点1）は「デリミタごとスパンを除去する」ことで、AW-7の`AWK_OPERAND_END_CHARS`/`AWL-4`（正規表現か除算かの曖昧ガード）に相当する仕掛けなしに閉じる。** sedの`s`/`y`はデリミタの直後の文字がそのまま区切り文字になり、除算のような曖昧な文法要素と衝突しない（awkの`/`が正規表現の開始か除算かで揺れるのとは異なり、sedの区切り文字は位置が構文的に確定している）。したがって「今読んでいる区切り文字が何か」を特定し、次に同じ文字が現れる位置までを機械的に除去すればよく、AWL-4相当の曖昧ガードは不要。

**結論:** sedのプログラム本文ホワイトリストは、awkより**条件が少なく**（1条件で足りる）、**曖昧ガードも不要**であり、investigatorが懸念した「区切り文字の任意性ゆえにawkより複雑になりうる」という論点は、**a/i/c（追加・挿入・変更。自由形式のテキスト引数）とb/t/T/:（分岐・ラベル。ほぼ任意の文字列を許すラベル名）を安全集合に含めない**という**明示的なスコープ限定**によって回避できる。これらのコマンドはリテラル除去に匹敵する専用の終端処理（a/i/cの自由テキストは改行まで、ラベル名は空白/`;`まで）を要し、そのための実装・検証コストは「日常の読み取り用途」（p/d/s///アドレス指定）に含まれないため、本チケットのスコープでは負わない。この2系統は**安全集合に含めない＝自動的にdeny**という形で処理し、AC6の新規deny列挙（§6 リスク R1）へ明記する。

**allowするコマンド（読み取り専用と確認できる狭い形）:**

| コマンド | 意味 | 安全と判断する根拠 |
|---|---|---|
| `p` `P` | パターンスペースの出力 | 標準出力のみ。ファイルI/Oなし |
| `d` `D` | パターンスペースの削除・次サイクルへ | sed内部状態の操作のみ |
| `n` `N` | 次の行の読み込み・追記 | 入力ストリームの通常の読み進めのみ |
| `g` `G` `h` `H` `x` | ホールドスペースとの相互操作 | sed内部状態（get/hold/exchange）の操作のみ |
| `l` | パターンスペースの非曖昧表示 | 標準出力のみ |
| `q` `Q` | 終了 | プロセス終了のみ。書き込み・実行なし |
| `s` `y` | 置換・変換 | パターン／置換文字列は除去（下記）。**フラグは`g`・`p`・数字のみ許可**（`e`・`w`は許可文字集合に含めないため、フラグとして出現しても自動的にdenyへ落ちる。`i`/`I`/`m`/`M`フラグは今回は未収載＝該当フラグを使う`s///`は新規denyとなる。§6 R1で明記） |
| `=` | 現在行番号の出力 | 標準出力のみ |
| `{` `}` `!` `;` | グルーピング・否定・区切り | 制御構文のみ。除去対象の内側でなければそのまま安全文字集合に含める |

**allowしない（安全集合に含めない＝自動的にdeny）コマンド:**

| コマンド | 除外理由 |
|---|---|
| `w` `W` | 本チケットの主眼（ファイル書き出し） |
| `r` `R` | 外部ファイルの読み込み（情報開示の経路。investigator Evidence論点5） |
| `e`（コマンド／`s///e`フラグ） | 任意コマンド実行（KLK-010 D6-3でスコープ外とした穴。本ホワイトリストで自動的に閉じる副次効果＝AC3が許容する範囲） |
| `a` `i` `c` | 自由形式テキスト引数（改行までの終端処理が必要。本チケットのスコープでは対応しない） |
| `b` `t` `T` `:` | 分岐・ラベル（ラベル名がほぼ任意の文字列。本チケットのスコープでは対応しない） |
| `z` `F` `v`（GNU拡張） | 利用頻度が低いため未収載。安全性確認後に追加チケットで許可文字集合へ加える余地を残す |
| 上記以外の未知の1文字コマンド | 機械的既定として自動deny（AW-7の「未知の呼び出し名はdeny」と同じ性質） |

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `w`/`W`の直前文字パターンを正規表現で拡張列挙する（`SED_WRITE_RE`の改修のみ） | KLK-010がawkで4ラウンド繰り返した「規則の積み増し」と同じ失敗パターンになる（アドレス構文・区切り文字の組み合わせを列挙し切れず、次の穴が出る）。人間承認済み方針（決定1）が明示的に退けている |
| `a`/`i`/`c`・`b`/`t`/`T`/`:`を自由テキスト・ラベルの終端処理込みで安全集合へ含める | 本チケットの日常読み取り用途（p/d/s///アドレス指定）に含まれず、実装・検証コストに見合わない。含めないことによる新規denyは「安全側」（P8）であり、必要になれば追加チケットで安全性を確認して収載できる |
| sedを`ALLOWED_HEADS`から外す | 人間決定1で明示的に却下済み（再度Open Questionとして問い直さない） |
| `-f SCRIPT`の中身を読み込んで検査する | 外部ファイルの内容はhookから不可視であり、KLK-010 D6-3のスコープ外判断を覆す新たな上位判断が要る。本チケットのスコープ外（チケット本文の明記どおり） |
| degraded経路にもSED-7ホワイトリストを適用する | degradedは空白分割でプログラム本文の同一性が失われる（`"1w SPEC.md"`のクォートが外れ`'`文字がそのまま残る等）ため、awkのAW-7がdegradedを対象外とする（AW-5/AW-6へ縮退する）のと同じ理由でsedも対象外とする。degradedでは既存の`SED_WRITE_RE`を維持する（§6 リスクR6） |

## 4. 実装詳細

### 4-1. 新設する定数（`.claude/hooks/guard_bash_writes.py`。`SED_INPLACE_SHORT_RE`/`SED_WRITE_RE`の定義直後に追加する）

```python
# --- SED-7: sed プログラム本文のホワイトリスト（KLK-015・AW-7と同型） ------
#
# sed のコマンド集合は単一文字であるため、AW-7 の「呼び出し名の許可集合」
# （条件2）は「許可文字集合」（条件1）へ吸収され、「出力構文の順序条件」
# （条件3）も不要になる（sed には print のような「安全な位置」が無く、
# w/W/r/R/e はどこに現れても危険なため、除去されずに残っていれば無条件に
# deny してよい＝ KLK-010 §3-1 P8）。
#
# 許可するコマンド（読み取り専用と確認済み。理由は docs/designs/KLK-015.md
# §3 の表を正とする）:
SED_SAFE_COMMANDS = frozenset("pPdDnNgGhHxlqQsy=")

# アドレス構文（行番号・$・,・!・~・+）とグルーピング（{}・;）・空白。
# デリミタそのもの（s/y のデリミタ・アドレス正規表現のデリミタ）は
# sed_strip_literals がスパンごと除去するためここへ含める必要はない。
# awk の // と異なり sed のデリミタは位置が構文的に確定しており、
# 「正規表現か除算か」で揺れる曖昧さが無いため AWL-4 相当の曖昧ガードも
# 不要である。
SED_SAFE_STRUCTURAL_CHARS = frozenset("0123456789$,!~+;{} \t\n")

SED_SAFE_PROGRAM_CHARS = SED_SAFE_COMMANDS | SED_SAFE_STRUCTURAL_CHARS

# sed が実際にプログラムとして実行するテキストを供給するオプション。
# -f／--file の値は外部スクリプトファイル名でありプログラム本文ではない
# （中身は不可視のまま＝ KLK-010 D6-3・INV-SED-05 のスコープ外を維持する）。
SED_PROGRAM_TEXT_FLAGS = ("-e", "--expression")
SED_SCRIPT_VALUE_FLAGS = ("-e", "-f", "--expression", "--file")
```

### 4-2. 新設する関数（`awk_program_texts`/`awk_program_violation`の近傍に追加する。配置は「awkのプログラム本文」ブロックの直後を推奨）

```python
def sed_strip_literals(text):
    r"""sed プログラムのアドレス正規表現・s/y のパターン＋置換文字列を除去する。

    **不変条件（P8）— 除去は「sed が実行しないテキスト」の部分集合でなければ
    ならない。開始条件と終端条件を対で規定し、終端が確定できない位置では
    除去せず None（判定不能→deny）を返す。**

    - **アドレス正規表現 `/…/`**: 未エスケープの `/` から次の未エスケープの
      `/` まで。改行に達したら未終端（sed の正規表現は改行をまたげない）。
      デリミタごと除去する（残す情報が無いため。awk の `//` 空literalとは
      異なり、除去後に「ここに正規表現があった」という痕跡を残す必要が無い
      ——後続の文字だけで安全性を判定できるため）。
    - **カスタムデリミタのアドレス正規表現 `\cXXXc`**（GNU/POSIX拡張）:
      `\` の次の1文字をデリミタとし、同様に未エスケープの再出現まで除去する。
      デリミタが `\` または改行なら不正な形として None を返す。
    - **`s`/`y` のパターン＋置換文字列**: `s`/`y` の次の1文字をデリミタとし、
      未エスケープの再出現を2回見つけるまで除去する（`s`/`y` を含めて3回の
      デリミタ出現＝2つの内容スパン）。コマンド文字（`s`/`y`）自体は
      **安全文字として残す**——`SED_SAFE_COMMANDS` に含まれるため。
      2回目の再出現が見つからない、または途中で未エスケープの改行に
      達した場合は None を返す。**除去後に残るのは s のフラグ領域だけであり、
      フラグに `w`/`e` が含まれれば安全文字集合に無いため自動的に deny
      になる**（`g`/`p`/数字のみ許可。`i`/`I`/`m`/`M` は本改訂では未収載＝
      新規deny・§6 リスク R1）。
    - **上記以外の文字**: そのまま残す（安全性は呼び出し側の
      `sed_program_violation` が `SED_SAFE_PROGRAM_CHARS` で判定する）。

    戻り値: 除去後テキスト。**判定不能（デリミタが閉じない）は None。**
    """
    out, i, n = [], 0, len(text)
    while i < n:
        ch = text[i]
        if ch in ("s", "y"):
            if i + 1 >= n:
                return None
            delim = text[i + 1]
            if delim in ("\\", "\n"):
                return None
            j, found = i + 2, 0
            while j < n and found < 2:
                c = text[j]
                if c == "\\":
                    j += 2
                    continue
                if c == delim:
                    found += 1
                    j += 1
                    continue
                if c == "\n":
                    break
                j += 1
            if found < 2:
                return None
            out.append(ch)  # コマンド文字は安全文字として残す
            i = j
            continue
        if ch == "/":
            j, closed = i + 1, False
            while j < n:
                c = text[j]
                if c == "\\":
                    j += 2
                    continue
                if c == "/":
                    closed = True
                    break
                if c == "\n":
                    break
                j += 1
            if not closed:
                return None
            i = j + 1  # デリミタごと除去（残す情報が無い）
            continue
        if ch == "\\":
            if i + 1 >= n or text[i + 1] == "\n":
                return None
            delim = text[i + 1]
            j, closed = i + 2, False
            while j < n:
                c = text[j]
                if c == "\\":
                    j += 2
                    continue
                if c == delim:
                    closed = True
                    break
                if c == "\n":
                    break
                j += 1
            if not closed:
                return None
            i = j + 1
            continue
        out.append(ch)
        i += 1
    return "".join(out)


def sed_program_texts(words):
    """sed が**プログラムとして実行する**テキストを列挙する（AW-7の
    `awk_program_texts` と同型）。

    - `-e TEXT` / `-eTEXT` / `--expression TEXT` / `--expression=TEXT` の値
      （複数可。GNU sed は複数指定時に改行で連結して1つのプログラムにする）
    - `-e` も `-f`（`--file` 含む）も無い場合に限り、位置引数の**先頭の
      オペランド**（sed は最初の非オプション引数をプログラムとして扱い、
      2番目以降は入力ファイル名として扱う）
    - `-f FILE` / `--file=FILE` の値は**プログラム候補に含めない**
      （中身が不可視の外部ファイル＝ KLK-010 D6-3 のスコープ外を維持する）。
      `-f` が存在する場合、位置引数はすべて入力ファイル名であり
      **フォールバックの「先頭オペランド」判定も行わない**
      （行うと入力ファイル名を誤ってプログラム本文として検査してしまう）
    """
    texts, positionals, expect, has_f = [], [], "", False
    for word in head_args(words):
        if expect:
            if expect in SED_PROGRAM_TEXT_FLAGS:
                texts.append(word)
            else:
                has_f = True
            expect = ""
            continue
        if word in SED_SCRIPT_VALUE_FLAGS:
            expect = word
            continue
        if word.startswith("-e") and len(word) > 2:
            texts.append(word[2:])
            continue
        if word.startswith("--expression="):
            texts.append(word[len("--expression="):])
            continue
        if word.startswith("-f") and len(word) > 2:
            has_f = True
            continue
        if word.startswith("--file="):
            has_f = True
            continue
        if word.startswith("-"):
            continue
        positionals.append(word)
    if not texts and positionals and not has_f:
        texts.append(positionals[0])
    return texts


def sed_program_violation(text):
    """プログラム本文が「安全と確認できる形」でなければ理由を返す（SED-7）。

    **ホワイトリスト。** リテラル除去後のプログラムが `SED_SAFE_PROGRAM_CHARS`
    のみで構成されていることを要求する。未知の文字・未収載のコマンド
    （`w`/`W`/`r`/`R`/`e`/`a`/`i`/`c`/`b`/`t`/`T`/`:` 等）はすべて deny 側へ
    落ちる。
    """
    stripped = sed_strip_literals(text)
    if stripped is None:
        return ("sed プログラムの字句を確定できません（アドレス正規表現、"
                "または s/y コマンドの区切り文字が閉じていません）。安全と"
                "確認できるプログラム形に限り許可します")
    unsafe = [c for c in stripped if c not in SED_SAFE_PROGRAM_CHARS]
    if unsafe:
        return ("sed プログラムに許可されていないコマンド／文字 %r があります"
                "（w/W・r/R・e・a/i/c・b/t/T 等の書き込み・情報開示・実行・"
                "分岐系コマンドは許可されていません）" % unsafe[0])
    return None
```

## 7. マイグレーション戦略

データ・永続状態の移行は**なし**（hookは毎回プロセス起動で状態を持たない）。段階的移行の注意点:

1. **判定集合を変える唯一の変更はPhase 1（検出ロジック実装）である。** 変化は (a) allow→deny（AC1・AC2・AC3が要求する新規deny全形＋R1に列挙した副次的な新規deny） (b) deny→allowになる形は**存在しない**（本設計はいずれも「除去しない＝deny方向」の追加であり、既存のdeny判定を緩める変更を1つも含まない）。
2. **有効化タイミング:** `.claude/settings.json`が参照する`guard_bash_writes.py`は、worktree内の変更がdevelopへマージされるまで実行時の判定に反映されない（KLK-010と同じ運用上の注意）。
3. **後方互換:** hookの入出力契約（PreToolUseのstdin JSON・`hookSpecificOutput.permissionDecision`・exit 0）は変更しない。deny理由文に新規1種（sedプログラムの許可されていない文字／コマンド）が加わるが、既存テストは理由文字列をassertしていない。
